维护方式：

1. 一行一张已有任务卡，引用原卡，不在这里拆施工批次、角色或复核步骤。跨仓引用使用 `仓名:仓相对路径`，已有工作区时补上恢复入口。
2. 首次关联/恢复时，在各卡既有 `execution_strategy.md`（交互单会话用既有进度工件）登记本表的 `dh-relay:<仓相对路径>` 与维护会话。维护会话在等待变化、卡级结果变化、停下或交棒时更新对应行和核对日期；多卡并行由各卡提供待更新内容及原证据位置，维护会话顺序汇总，不并写本表，不需要保持 agent 在线。非维护卡写好待更新行后，由其 orchestrator 向维护会话发一行 Herdr prompt `[relay-light] card-chain update <卡号> <交接工件仓相对路径>`，维护会话先核原证据再汇总；通知不可达走第 6 条“总表待同步”。维护会话所在卡在收口汇报前必须先移交维护权：默认交给下一张已开工且关联本表的卡的 orchestrator（多张按总表行序取首张，用户可另行指定），没有则交回用户（页头写“维护会话：待指定（用户）”）。移交时交出方 Herdr prompt 通知接收方（`[relay-light] card-chain maintainer-handoff <总表仓相对路径>`），接收方在自己的交接工件登记并回一行确认，交出方收到后才改本表页头和自己的登记；接收方未确认/不可达按交回用户处理。未完成移交不算收口。
3. 恢复时先读原卡和工作区证据，核对接棒条件；施工结束、复核通过、合入和验收通过不能混用。只有交接条件有证据支持才写“已交棒”，并在条件栏保留证据引用；它不等于原卡已全部完成，本身也不授权下一卡开工。下一卡自动开工只看该行「自动接续」栏：只由用户写定（页头记来源指针），维护会话与 orchestrator 不得改写；写「是」并写定下一卡 orchestrator 模型档的卡，由维护会话（本卡收口移交前，或收到非维护卡收口通知时）核对接棒条件（全部前置有证据），完成开局准备（Issue / 分支与 worktree / Draft MR/PR / 新 Herdr workspace）并拉起该卡 orchestrator，多张满足条件时逐张全部拉起、维护权交行序首张；彼此不是前置且允许路径不重叠的多张未开工「是」卡也可在首次关联/恢复核表或用户新写定「是」时同时各开 space 并行推进（SKILL「并行开卡」），这种非收口触发不移交维护权，维护权始终单一，并行期间各卡只登记待用户决定事项并通知，由维护会话按卡分组一次问用户再逐卡转回答复；「否」或空白只核对、报告用户等放行；任一步失败只停该卡，写「等待：<原因>」并在汇报列出已建半成品，不重试、不临时索要分配。规则原文见 SKILL「自动接续」。
4. 原卡及 DevPlan 是任务与依赖的权威。总表只是摘要；不一致时先核对纠正，缺证据就写“待核实”。改变依赖或新增任务仍按原仓流程处理。

5. 交棒前由维护会话核对当前行状态、下一步/等待原因、交接证据及核对日期，在既有交接/汇报写一行「总表已核对：<路径>；<卡号>；<日期>」。版本交接引用提交 SHA；只通过批次复核不能写整卡已完成。
6. 无法更新（路径缺失、维护人不可用、无写权或冲突）时，本卡既有交接工件保留待更新内容和证据位置，报告“总表待同步”；不宣称已交棒，不依赖旧摘要放行后续，不阻断无关已授权卡内工作。
7. 完整规则见 dh-relay 仓 `tools/relay-light/skill/SKILL.md`「卡级总表维护与交棒核对」。这是会话流程检查，没有自动同步程序；不增加 worker/watcher 写权、常驻 agent、账本或运行状态来源。自动接续（含并行开卡）只由维护会话一次性拉起下一卡 orchestrator，不设跨卡常驻编排，不绕过各卡「自动接续」栏与接棒条件。
