维护方式：

1. 一行一张已有任务卡，引用原卡，不在这里拆施工批次、角色或复核步骤。跨仓引用使用 `仓名:仓相对路径`，已有工作区时补上恢复入口。
2. 首次关联/恢复时，在各卡既有 `execution_strategy.md`（交互单会话用既有进度工件）登记本表的 `dh-relay:<仓相对路径>` 与维护会话。维护会话在等待变化、卡级结果变化、停下或交棒时更新对应行和核对日期；多卡并行由各卡提供待更新内容及原证据位置，维护会话顺序汇总，不并写本表，不需要保持 agent 在线。
3. 恢复时先读原卡和工作区证据，核对接棒条件；施工结束、复核通过、合入和验收通过不能混用。只有交接条件有证据支持才写“已交棒”，并在条件栏保留证据引用；它不等于原卡已全部完成，也不授权下一卡开工。
4. 原卡及 DevPlan 是任务与依赖的权威。总表只是摘要；不一致时先核对纠正，缺证据就写“待核实”。改变依赖或新增任务仍按原仓流程处理。

5. 交棒前由维护会话核对当前行状态、下一步/等待原因、交接证据及核对日期，在既有交接/汇报写一行「总表已核对：<路径>；<卡号>；<日期>」。版本交接引用提交 SHA；只通过批次复核不能写整卡已完成。
6. 无法更新（路径缺失、维护人不可用、无写权或冲突）时，本卡既有交接工件保留待更新内容和证据位置，报告“总表待同步”；不宣称已交棒，不依赖旧摘要放行后续，不阻断无关已授权卡内工作。
7. 完整规则见 dh-relay 仓 `tools/relay-light/skill/SKILL.md`「卡级总表维护与交棒核对」。这是会话流程检查，没有自动同步程序；不增加 worker/watcher 写权、常驻 agent、账本或运行状态来源。
