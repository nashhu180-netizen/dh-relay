## 0. B 方案审核与理解确认

- **事件类型**：B-新建（`DHR-B-03`）。本计划**独立于 `P2-完整流水-开发方案.md`**，不改它、不占它的 B1～B18 / H3～H5 任何一项、不进它的覆盖对照表与完工条件。

- **⚠️ 设计依据的诚实登记**：本计划承接的 [`design/03`](../design/03-完整流水-Herdr底座-产品设计与验收.md) **是草案，尚未交叉审核、尚未经用户确认、尚未进入 `design/README.md` 白名单**。按 dev-harness 常规，B 拆计划的依据应是白名单正式输入，本计划是**登记在案的例外**，理由与边界如下：
  - **为什么必须例外**：`design/03` 的 P0 前置闸 `H-A8-1`（用户亲判 Herdr 交互体验）**只能靠真跑来判**；真跑需要 relay 有 herdr 适配器；不排卡就形成死锁——不做适配器 ⇒ 判不了闸 ⇒ 方案永远确认不了 ⇒ 永远不排适配器。
  - **例外的边界**：本计划**不宣称** `design/03` 已确认，**不把** `design/03` 的 `B19～B26` / `H6～H8` 当作已生效验收项（本计划自用 `P1～P8` / `HP1～HP3` 独立编号）；`design/03` 若最终被采纳，届时按 `DHR-B-04` 正式重拆并作废本计划的编号。

## 1. 概述

- **交付什么**：① 把 relay 的终端后端从"写死 psmux"改成**显式可配置**（`psmux` / `herdr` / `fake`），psmux 路径行为零变化、仍为默认；② 实现 herdr 终端适配器（与现有六动词契约同外形）；③ 用一张真卡完整跑一趟，取得判定 Herdr 底座去留所需的全部证据与用户人判。
- **不含什么**：不做 `design/03` 的 `H5`（确认闸护栏改造）、`H6`（宿主指纹冻结与漂移分级）、`H7`（完整"在等人"提示回路）、`H9`（工作树信任预置）、`H11`（agent-console 托管）——这些都是 `design/03` **被采纳之后**才排的卡；不改 `relay/v2` 契约本体；不改 psmux 适配器行为；不碰 dh-crew 与 agent-console 两个仓；不做 orca 任何形态的承载。
- **承接设计**：[design/03](../design/03-完整流水-Herdr底座-产品设计与验收.md) 的 `H1`（拓扑）、`H2`（句柄纪律）、`H3`（probe 语义）、`H8`（失联判定）、`H10`（双后端并存）与前置闸 `H-A8-1`；机器事实全部取自 [design/evidence/03](../design/evidence/03-Herdr底座-preflight实测与审核记录.md) 的 `E-A8-01～11`。
- **实施策略一句话**：先把后端选择这条缝**在不引入任何新后端的前提下**开出来并证明 psmux 零回归，再把 herdr 适配器挂上去，最后拿真卡跑一趟交用户判。
- **任务前缀 / 模块 slug**：`DHR_` / `dh-relay`，verify scope = `dh-relay`；任务 ID `DHR_22～DHR_24`（`DHR_04～DHR_21` 已被 P2 占用）。
- **卡数说明**：三张。不能压成一张——`DHR_22` 与 `DHR_23` 分属两个安全边界（前者改所有后端共用的选择点、后者引入一个全新的外部宿主依赖），且 `DHR_22` 的去留与 `H-A8-1` 无关而 `DHR_23` 有关，合卡会让判否时的回退面糊掉。`DHR_24` 是人判卡，与实现卡合并会出现"实现者判自己"的问题。

### 2.3 与 P2 的并行约束

- **路径不重叠**：本计划改 `adapters/` + host 装配缝；在飞的 `DHR_04` 改 `policy/`。但**合入顺序须串行**，且以先到者为基线、后到者 rebase 后重跑闸。
- **P2 不受影响**：`DHR_05～DHR_21` 的依赖链、批次切分与覆盖分账与本计划无关；本计划不新增对 P2 任一验收项的覆盖责任，也不解除任何。
- **默认值不变**：本计划落地后，未显式配置 `backend` 时 relay 行为与今天**逐字节一致**（psmux）。这是 `DHR_22` 的硬验收（`P3`）。

### 3.2 任务卡

#### DHR_22

- **目标**：把 relay 的终端后端由写死 psmux 改为显式可配置（`psmux` / `herdr` / `fake`），并以机器证据证明**未配置时行为与改动前逐字节一致**。本卡**不引入任何新后端实现**。
- **非目标**：不实现 herdr 适配器（归 `DHR_23`）；不改 psmux/fake 适配器的任何判据、阈值或回参；不改 `relay/v2` 契约；不做后端相关的产品能力（提示回路、护栏改造等）。
- **验收口径**：
  - **机器证 `P1`**：后端枚举与解析——`backend ∈ {psmux, herdr, fake}` 由注册表条目与运行参数两条来源解析，优先级冻结并有正例；**未知值、空值、大小写不符一律 fail-closed 拒绝启动**（各一反例），不得静默回落到默认。
  - **机器证 `P2`**：装配点唯一——全仓只有一处根据 `backend` 装配适配器；以静态检查证明不存在第二处后端分支，也不存在绕过装配点直接引用具体适配器的代码路径（反例：新增一处旁路引用即失败）。
  - **机器证 `P3`（本卡核心）**：**默认行为零变化**——未显式配置 `backend` 时，psmux 路径的六动词回参、事件序列与全部现有套件断言与改动前**完全一致**；`P1`/`P2` 现役全部套件绿，且 psmux 相关套件**一条断言都未被修改**（以 diff 证明测试文件未被放宽）。
  - **机器证 `P4`**：`herdr` 枚举值在本卡阶段的处置——配置为 `herdr` 时因适配器尚未实现，须给出**明确的未实现错误**并 fail-closed，不得半启动、不得静默回落 psmux（正反例各一）。
- **变更范围**：`tools/adapters/`（新增装配/选择模块）、`tools/host/` 的适配器装配缝（最小改动）、`tools/tests/`；本卡 workspace。
- **档位**：标准（改的是所有后端共用的装配点，影响面覆盖全部现役路径）。
- **实施提示**：
  - 先写 `P3` 的零回归证据再改代码——**基线快照必须在动手前取**，事后补取等于自证。
  - 装配点做成纯函数（输入配置、输出适配器实例），可注入，便于 `DHR_23` 挂新后端时不再动 host。
  - `P4` 的"未实现"分支在 `DHR_23` 完成后会被真实现替换，届时该反例转为正例，须在 `DHR_23` 显式交接。

#### DHR_23

- **目标**：实现 herdr 终端适配器（六动词，与 psmux/fake 完全相同的九键回参外形），接进 `DHR_22` 的装配点，并证明它在真实 herdr 会话下可用、句柄不会串、失败不留孤儿。
- **非目标**：不做 `design/03` 的 `H5`/`H6`/`H7`/`H9`/`H11`；不改 psmux 行为；不改契约；不做实战与人判（归 `DHR_24`）。
- **验收口径**：
  - **机器证 `P5`**：六动词在真实 herdr 临时命名会话下可用且外形不变——launch 成功与失败各一；probe 覆盖 `working/idle/blocked/done/unknown` **五态映射**（依 `design/03` `H3`：`blocked` 映射为 `idle` 并另出旁路提示，**不新增业务状态、不改合法转换边**）；stop 后须「pane 不在 ∧ 进程不在」才判 `exited`，只缺其一报 `probe_error`（沿用 `F-022` 教训，在 herdr 上重证）；**launch 任一失败分支不留孤儿 pane**。
  - **机器证 `P6`**：句柄纪律（`design/03` `H2`）——agent 名规范化规则冻结，超长与非法字符**不得静默截断**（各一反例）；每次操作回读 `pane_id` 与 receipt 比对，外部移动 pane 后拒绝继续而非误操作；以静态检查证明不存在以窗口标题、UI 焦点或 pane 序号定向的代码路径。
  - **机器证 `P7`（安全关键）**：**启动信任弹窗不得被误判为启动成功**——全新未信任路径下 launch，即使 herdr 报 `agent_status=idle` 且 `interactive_ready=true`（[E-A8-03](../design/evidence/03-Herdr底座-preflight实测与审核记录.md) 实测形态），也**必须** fail-closed 报 `launch_failed`，不得记成功。**这是本卡最关键的反例**：该形态比 psmux 的"屏幕没变"更容易骗过 Runner。
  - **机器证 `P8`**：跨后端等价——同一份 fake 回放剧本分别以 `psmux` 与 `herdr` 执行，业务事件序列全等；允许差异的字段（宿主指纹、句柄）列白名单并**逐字段断言**，不得用"整体近似"糊过去。`DHR_22` 的 `P4` 未实现反例在本卡转为正例并交接。
- **变更范围**：新增 `tools/adapters/herdr-adapter.ps1`、`tools/tests/relay-herdr-adapter.ps1`、`tools/tests/relay-backend-equivalence.ps1`；本卡 workspace。
- **档位**：标准（引入全新外部宿主依赖 + 一条安全关键的 fail-closed 边界）。
- **实施提示**：
  - 拓扑按 `design/03` `H1`：一 run 一命名会话、一卡一 tab、一棒一 pane；**不使用** herdr 的 workspace/worktree 原语（树由 dev-harness 管，两套必漂）。
  - 逐 profile 环境注入用 `pane split --env KEY=VALUE`（[E-A8-05](../design/evidence/03-Herdr底座-preflight实测与审核记录.md) 实测可用）。
  - 因 herdr **无 pane 退出事件**（`E-A8-04`），失联判定保留轮询 + `pane.process_info` 进程探测兜底（`design/03` `H8`）。
  - 事件订阅（`events.subscribe`）在本卡**可不接**；若接，须遵 `H4`——只用于提前触发 tick，**自己不改任何 active state**，权威仍是文件事件账。
  - herdr 为 preview 版且检测清单联网自动更新（`E-A8-07`）：本卡至少在 receipt 记 herdr 版本与 protocol，完整的冻结与漂移分级归 `H6`、不在本卡。

#### DHR_24

- **目标**：用一张真卡把 herdr 底座完整跑一趟，产出 `J1～J5` 对照表与用户人判，据此决定 `design/03` 采纳与否。
- **非目标**：不改任何生产代码（发现缺陷回 `DHR_22`/`DHR_23` 返工）；不代用户判断 `H-A8-1`；不修改 agent-console 仓关于 Herdr 的既有 no-go 结论。
- **验收口径**：
  - **机器证 `P9`**：实战可复算——完整运行现场（事件账、receipt、逐棒记录）留档，第三方可据其独立重算棒序与耗时；开跑前后各记一次 herdr 版本/protocol/manifest 指纹，期间若变则数据标注"跨版本"。
  - **人判 `HP1`（否决性）**：`design/03` 的前置闸 `H-A8-1` —— 用户亲自用完整一趟后判 **Herdr 交互体验是否可接受**。展示：使用体感 + 宿主侧延迟采样对照（herdr / psmux 同负载）+ 本趟窗口作答次数。**判否 → `design/03` 整份 retire，`DHR_23`/`DHR_24` 按 §0 理解问题的用户回答处置，`DHR_22` 保留。**
  - **人判 `HP2`**：`blocked` 提示的**真阳 / 假阳 / 漏报逐条清单**，用户判是否准到值得依赖。口径写死：**假阳比漏报更坏**——假阳会训练用户忽略提醒，故假阳率单独列示、不与漏报合并计分。
  - **人判 `HP3`**：双后端对照（总耗时、被打断次数与时机、异常与恢复次数、每卡人工动作数），用户判换底座是否**真的减少了等待与巡检**。
- **变更范围**：本卡 workspace 与 evidence；`D:\relay-stage0` 的一次受控刷新（留证）。**不改 `tools/` 任何生产代码。**
- **档位**：标准（真跑真卡 + 否决性人判）。
- **实施提示**：
  - **实战前必须显式刷新一次 stage0 冻结驱动器并留证**——`DHR_04` 走的是 `D:\relay-stage0`，herdr 适配器不在那份冻结里；直接拿工作树代码驱动真卡会破坏 `DHR_04` 自己立的隔离（跑的代码 == 被改的代码）。
