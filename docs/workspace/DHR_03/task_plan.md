## 关键决策（主控定·worker 照做，一句话各一行）

- **K-1 后端闸**：批0 用同一判据表对 psmux 与 orca 各做一次**原语级** preflight；psmux 默认；orca 只有全部判据 pass 且体验更优才由主控**停下向用户提议**修订设计决策 7（本卡不写 orca adapter）；psmux 任一判据 fail → 停"待环境"，不进批A。批A 收尾再跑一次 **adapter 级** preflight 作为 A7 正式证据。
- **K-2 句柄**：宿主 session 名 = `relay-<run_id>-<session_id>`（run_id/session_id 中非 `[A-Za-z0-9-]` 替换为 `-`）；adapter.launch 返回 `@{ok=$true; session_id=<receipt.session_id 原样>; handle=@{session_name; psmux_session_id; pane_id; pane_pid; client_pid; window_title}}`（Runner 只比 session_id，多余键忽略）；handle↔launch_id 1:1 登记 adapter 自己的 registry `<HandleRoot>/<session_id>.json`（字段：launch_id/session_id/session_name/psmux_session_id/pane_id/pane_pid/client_pid/window_title/launched_at/stopped_at/client_lost），adapter 是该目录唯一写者，**不写** Runner 的 launches/attempts/state/events。
- **K-3 精确匹配**：所有"存在/不存在"判定 = `list-sessions -F '#{session_name}|#{session_id}|#{session_attached}'` 逐行拆分后 `session_name -ceq <name>`；不用 `has-session`、不用 `-t =name`；同名多行（理论不可能）→ probe_error reason `ambiguous-session`。
- **K-4 可见/可交互**：launch 顺序 = 全等重名检查（有→`session-name-collision`）→ 清 PSMUX_SESSION → `new-session -d -s <name> -n <node_id> -- <LaunchCommand>` → `set-option -t <name> set-titles on` + `set-titles-string 'RELAY:#S'` → `Start-Process psmux attach -t <name>`（记 client_pid）→ 在 `AttachDeadlineSeconds` 内轮询直到 attached≥1 ∧ 标题全等可见窗口存在 → 写 registry → 返回；超期 → 先 `kill-session <name>`（不留孤儿）再返回 `@{ok=$false; reason='launch-not-visible'|'launch-not-attached'}`；new-session 非 0 → `psmux-new-session-failed`。
- **K-5 probe**：`list-sessions` 全等不在 → `@{ok=$true; terminal_state='exited'; probe_error=$false}`；psmux 命令失败（exit≠0 且非"no server running"类）→ `@{ok=$false; probe_error=$true; reason='psmux-command-failed'}`；在 → `list-panes -t <name>` 取 `window_activity`：`now - activity ≤ IdleAfterSeconds` → `running`，否则 `idle`；`pane_dead=1` → `exited`（会话即将消失）；attached=0 而会话在 → 不改终端状态，registry 记 `client_lost=$true`（P1 不重开窗口）。P1 adapter 不产生 `stopped`。
- **K-6 stop**：`kill-session -t <name>`（裸名）→ 在 `StopDeadlineSeconds` 内轮询 list-sessions 全等不存在 → `@{ok=$true; exited_after_ms=n}` 并 registry 写 stopped_at；超期 → `@{ok=$false; reason='stop-not-confirmed'}`；未知 session → `unknown-session`。
- **K-7 suspend/resume** 返回 `@{ok=$false; reason='not-used-in-p1'}` 只记 calls；**emit_observation** 返回 `@()`（psmux 无推送通道，P1 全靠 probe）。adapter 源码**不得**出现 `send-keys`/`paste-buffer`/输入类命令（无人工输入 API·静态扫描断言）。
- **K-8 命令执行缝**：adapter 一切 psmux 调用经 `$Exec`（scriptblock，`param([string[]]$Args)` → `@{exit; stdout; stderr}`；默认实现调真 `psmux`）；`$Clock` 注入（默认 UtcNow）；`$WindowProbe`（scriptblock `param($Title)`→bool，默认 user32 EnumWindows 全等）与 `$ClientLauncher`（scriptblock `param($Name)`→client_pid，默认 Start-Process psmux attach）同样可注入——离线套件全部注入假实现，真实套件用默认。
- **K-9 宿主循环（relay-host.ps1）**：Runner 仍是唯一状态写者；worker 只写 `attempts/<n>/<a>/{checkpoint.json.tmp, result.json.tmp, handoff.md, session-tail.txt}`；agent 侧提案写 `<run>/inbox/proposal-v<N>.json`（inbox 是宿主约定目录，非 Runner state）。每 tick：(1) 每个 `scheduling='launched'` 节点：`checkpoint.json.tmp` 存在→`Submit-RelayCheckpointFile`→改名 `checkpoint.json.tmp.consumed-<ticks>`；`result.json.tmp` 存在→`Submit-RelayResultFile`→改名 `result.json.tmp.consumed-<ticks>`（拒收也改名，原因已在 events；不重复摄入）；(2) `inbox/proposal-*.json`（按文件名排序）→`Submit-RelayProposal -ExpectedGeneration $run.state.authority_generation`→改名 `.consumed-<ticks>`；(3) `Invoke-RelayTick`；(4) `Get-RelayReadyNodes` 逐个 `Start-RelayNodeAttempt`；(5) `replan_required=$true` 且 host-state 记录的 `replanner_spawned_for_generation ≠ 当前 generation` → 调 `-ReplannerSpawner`（scriptblock `param($Run)`，一次性 agent；宿主自记 `host-state.json`，不进 Runner state）；(6) 首 tick 若无 active plan 且 inbox 空 → 调 `-OrchestratorSpawner` 一次；(7) 终止：无 `launched` 节点 ∧ ready 空 ∧ `replan_required=$false` ∧ inbox 无待摄入 ∧ 无 spawner 在途 → 退出 0；`-MaxTicks` 到 → 退出 2 并打印未完成节点。每 tick 打印**一行**面向用户的状态（`[relay-host] tick=n A=running/working B=… `），这一行计入 H2 通知数。宿主源码**不得**引用 `question|options|answer`、不调 suspend/resume（静态扫描断言）。
- **K-10 agent 侧工具（relay-agent-tool.ps1）**：子命令 `checkpoint`/`result`/`propose`；身份链**只**从 `$env:RELAY_RECEIPT`（receipt 绝对路径，worker-entry 注入）读出，agent 不手填；`result` 写前先写 `handoff.md`（首行 `<!-- dh:relay-handoff v1 plan_version=… session_id=… -->` 身份头 + 正文自 `-HandoffBody <file>`）+ `session-tail.txt`（`Invoke-RelayTailSanitize` 先脱敏再限长 `SessionTailMaxBytes`；来源 `-TailFrom <file>` 可选）+ git snapshot 元数据（`git rev-parse HEAD`/changed paths/`git diff --stat`，失败填 `'n/a'`）；产物两段写：`<file>.partial` → `[IO.File]::Move` 到 `<file>.json.tmp`；每个产物写前先过对应 `Test-Relay*`，不过→exit 4 并打印 reason（agent 看得见、可改）。`propose -PlanFile <json>`：读 agent 起草的 plan（可缺 plan_hash）→ 用 `Get-RelayPlanHash` 回填 → `Test-RelayPlanProposal` → 写 `inbox/proposal-v<N>.json`。
- **K-11 dogfood agent 配置**：worker = 可见交互 `claude`（`-WorkerCli claude|codex`、`-WorkerConfigDir` 可指 `CLAUDE_CONFIG_DIR`，默认主账号），由 `relay-worker-entry.ps1 -Receipt <path> -BriefRef <path> -Cli claude`（adapter 默认 LaunchCommand）设 env（`RELAY_RECEIPT`/`RELAY_RUN_ROOT`/`RELAY_ATTEMPT_DIR`/`RELAY_TOOL`）、`Set-Location` 到 `-WorkDir`、打印一行身份横幅（session_name/launch_id/attempt）后起 CLI，prompt=brief 全文（`claude "<brief>"` 交互态·`--dangerously-skip-permissions`；codex 用 `codex --yolo "<brief>"`）；orchestrator/replanner = 一次性 headless（默认 `claude -p --dangerously-skip-permissions`，`-PlannerConfigDir` 可换账号）读 dogfood fixture 写 proposal（走 `relay-agent-tool propose`）。
- **K-12 现场与证据**：dogfood 运行现场 `.dh-runtime/relay/<run_id>/`（gitignore `.dh-runtime/` 已覆盖）；证据拷入 `docs/modules/dh-relay/workspace/DHR_03/evidence/<scenario>/`：`events.jsonl`、`relay-state.json`（终态）、`launches/*.json`、`psmux-handles/*.json`、`host-state.json`、`timeline.md`（`Export-RelayTimeline` 从 events 生成：每行 event_id/时间/kind/node/attempt/session/reason，并在 launch/stop 行引用同刻截图文件名）、`shots/<event_id>-<session_name>.png`（宿主循环 `-ScreenshotOnLaunch`/`-ScreenshotOnStop`：`System.Drawing` 全屏截图 + 同刻 EnumWindows 标题列表写进 `shots/<event_id>.windows.txt`）。截图与机读事件互相对照 = 文件名含 event_id + windows.txt 含 `RELAY:<session_name>`。
- **K-13 A3 迟到结果**：blocked 场景跑完后，主控用 A attempt1 的旧 receipt 让工具生成一份**内容合法**的 succeeded result（`RELAY_RECEIPT` 指旧 receipt），走 `Submit-RelayResultFile` 真实入口 → 期望事件 `result_stale|A|1|stale-plan`（或 `stale-generation`）+ `relay-state.json`/`active-plan.json`/`authority.json` 字节不变；不得直接改 state 或用测试桩。
- **K-14 H2 口径**：人工动作数 = 用户显式确认/回答/重启（blocked 目标 0；decision 目标 1）；通知数 = 宿主每 tick 状态行数 + 主控转述给用户的消息数（分列）；blocked→fresh A hop 数 = 事件签名中 `result_accepted|A|1` 到 `launch_receipt|A|2` 之间的事件条数（含两端）+ 可见步骤数（用户能在窗口看到的步骤）；对照组 = dh-crew 常驻主控巡检，只引用已有记录（design/10 + DCR_47 dogfood 手记）不重跑；未覆盖范围列在同表。
- **K-15 Runner core 只扩不改**：若 adapter/宿主接线时发现 Runner 需要改判定（如 exited 后 stop 的处理、`launched.session_id` 之外的键），worker 记 findings + DONE blocked，主控裁决；允许的扩展 = 新函数、可选参数、README/注释。
