## 0. 这份草案怎么来的

- **用户原始诉求（逐字）**：「我想做成可编排的流程引擎」；追问目的答「dev-harness 可以和其他流程拼接。比如：做完一个任务更新周报。未来的dev-harness修改.」
- **第一版设想被否**：主会话最初提的是「用一张 5 条红线的**不变量校验器**替代模板语义等价校验」。经 `codex / gpt-5.6-sol / reasoning=xhigh` fresh 交叉评估，判 **不通过·存在 P0 级授权缺口**（评估全文见 `evidence/04`，待落盘）。
- **P0 的实质**：**红线清单 ≠ 授权清单**。模板不只是形状检查，它同时**框死了 planner 能发起的动作集合**。撤掉模板后 planner 从「填表人」变成事实上的**权限授予者**——可以选用户从未授权的 prompt、脚本、外部动作。卡号合法 ≠ 动作合法，B14 不再闭合。
  - 佐证：现役 schema 已允许计划自填任意 `brief_ref`（`tools/contracts/relay-schema.ps1:91`）；现役合法 fixture 里就躺着一个无依赖、无后继的孤儿节点 E（`tools/tests/fixtures/plans/plan-v1-chain.json:13`）。**「合法 DAG」离「完整授权流水」很远。**
- **原 5 条草案里有 3 条本身语义就是错的**（详见 §5 已知偏差表）。
- **转向**：改采 codex 建议的**两层模型**，并经用户三项拍板成形（见 §1）。

## 2. 人话版目标

把 relay 从「只会跑一条写死的 dev-harness 流水」，改成「能把若干个**有版本号的流程宏**拼成一张图来跑」。

- **外层**：宏与宏之间自由连线（DAG）。
- **内层**：每个宏**内部固定**。`dev_harness_card@v1` 内部仍是今天那套棒序，仍走模板语义等价校验，**一条断言都不放宽**。
- **演化方式**：想改卡内流程 → 发 `@v2`。snapshot 冻结版本号，老 run 绑老版本、不受影响。
- **外部效果**：relay **不直接**跨仓写、不直接调外部 API。它只发一条不可变事件；由另一条**独立授权**的链去消费。

一句话：**自由在宏之间，冻结在宏之内；卡内演化走版本发布，不走运行时编排。**

### 2.1 为什么两层比全引擎更配这两个诉求

| 诉求 | 两层模型 | 全不变量引擎 |
|---|---|---|
| 和别的流程拼接 | 外层挂个新宏，零引擎改动 | 同样能做，但要先把 16 条不变量全建起来 |
| dev-harness 以后要改 | 发新版本模板；老 run 纹丝不动 | 改护栏=改校验器代码，要重证其余不变量未被破、重跑变异探针、**影响所有在飞 run** |
| 改护栏的可回溯性 | 有版本号、可 diff、可回滚 | 校验器代码变更，回溯靠 git 而非流程版本 |

**唯一做不到的**：在不发版本的前提下临时重排某张卡内部的棒。但那本就不该允许——卡内流程就是质量护栏，每次改都应是一次有版本号、经过审核、可回溯的变更。

## 3. 核心决策清单（改它牵动 ≥3 处）

| # | 决策 | 理由 / 反面 |
|---|---|---|
| C1 | 两层：外层图 + 内层冻结宏 | 见 §2.1 |
| C2 | 宏有 `workflow_id + version + content_hash`，由 authority snapshot 冻结 | 不冻结 → 计划通过后换宏实现（codex 不变量 #2） |
| C3 | **授权公式 = `计划的副作用 ⊆ 授权的许可`**，不是「红线清单」 | 这是 codex 逮出的 P0。红线只说不能做什么，证明不了剩下的都获准 |
| C4 | 卡内演化=版本发布，非运行时编排 | 用户 D1 |
| C5 | 外部效果走 outbox，relay 不拿跨仓写权 | 用户 D2/D3。**副作用：design/02 §7「不做跨仓 run」原样保住，P2 不必为此破例** |

**原 5 条不变量草案中语义就错的 3 条**（已废弃，登记备查）：

| 原草案 | 错在哪 |
|---|---|
| ≥2 个**不同 `profile_id`** 的复核 | `design/02:59` 正式口径是「账号可同、**会话必不同**」。`profile_id` 只是注册表标签，两个 profile 可映射同一账号 → 既**误放**（同账号被认作独立）又**误杀**（合规的同账号复核被拒） |
| 每卡**恰好一个** finalizer | 与取消语义冲突：closeout 前取消的卡本就没有 finalizer（`design/02:68` cancelled-exempt） |
| `lesson_review` 必须**存在**且在 closer 前 | B18 要的是真 launch + result + 落到三终态之一（`design/02:278`）。图里有节点 ≠ 它真跑过 |

- 不改 `design/02` 的远端 test 权限边界（B16/H5 继续独立）。
- 不在本草案阶段动任何生产代码；不改任何在飞任务卡的验收口径。
