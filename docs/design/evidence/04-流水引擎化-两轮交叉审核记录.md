## R1 · codex 评估（第一版：红线清单 / 不变量校验器）

### 结论
> 按现有 5 条不变量直接替换模板等价校验，**不通过。存在 P0 级授权缺口。** 不变量路线理论上可行，但必须升级成一套「计划只能收窄授权、不能创造授权」的完整策略系统；这不是改写 B14 一条验收即可完成的局部调整。

### P0-1 · authority snapshot 到计划之间的授权链断裂
现设计由 snapshot 冻结卡/目标/验收/范围，再由固定模板决定「会执行哪些动作」；planner 只能填槽位。换成「planner 交任意图」后，**snapshot 没有授权节点类型、brief、script/profile、外部副作用或流程版本**。

- 佐证：`design/02:38`、`:52`、`:159`；B14 用户复核只展示卡清单与主题（`design/02:274`）；现役 schema 允许计划自行给任意 `brief_ref`（`relay-schema.ps1:91`）。
- 影响：planner 从「填表人」升级成事实上的**权限授予者**。卡号合法 ≠ 动作合法，B14 不再闭合。
- 建议：安全公式改为 `Plan effects ⊆ Authority grants`；B14 应拆成「授权签发」与「计划策略准入」两个独立安全边界，不能继续塞在 DHR_12 一张卡。

### P0-2 · 5 条草案远不足以证明一张卡真的走完了流水
现役图校验只检查字段、依赖存在与无环（`relay-schema.ps1:112/131/145`）；合法 fixture 已包含完全独立的孤儿节点 E（`plan-v1-chain.json:13`）。**「合法 DAG」≠「完整授权流水」。**

codex 列出若坚持全动态图则**缺一不可的 16 条不变量**（每条附不补时的绕法）：授权集合闭包 / 工作流与策略版本冻结 / 能力与副作用子集 / brief 与输入来源绑定 / 全图可达性 / 逐卡支配关系 / 结果守卫 / 当前候选绑定 / 独立性与 fresh 证据 / 变更失效传播 / 返工与重编排单调性 / 执行者真实性 / 取消与 finalizer 基数 / run 生命周期闭包 / 外部动作幂等与补偿 / 资源上限与运行期复验。

### P1 · 原 5 条里三条语义本身不正确
| 原草案 | 错在哪 |
|---|---|
| ≥2 个不同 `profile_id` 的复核 | `design/02:59` 正式口径是「账号可同、会话必不同」；`profile_id` 只是注册表标签，两个 profile 可映射同一账号 → 既误放又误杀 |
| 每卡恰好一个 finalizer | 与 cancelled-exempt 冲突（`design/02:68`） |
| `lesson_review` 必须存在且在 closer 前 | B18 要真 launch + result + 三终态（`design/02:278`）；图里有节点 ≠ 它真跑过 |

### P0-3 · 「更新周报」没有现成授权主体
archive 是写死目的地/权限/事务语义的特权 run-level script（`design/02:67`、`:172`）；B9 当前白名单不含周报路径（`design/02:269`）；跨仓 run 仍明确不做（`design/02:290`）。
> archive 证明「run 节点能存在」，**不证明「任意外部效果已获授权」**。
建议默认方案为 durable outbox。

### P1 · 「现在改 P2」时点对，但受影响清单严重偏少
主会话原判 5 张（05/10/11/12/18），codex 核出至少 **12 张**：04/05/07/09/10/12/14/15/18/19/20/21。并指出 `DHR_11` 大概率**不**受影响、`DHR_06` 基本不受影响、`DHR_17` 不应泛化成「所有外部写入」大口袋。

### P1 · P3 不应被牵连
`DHR_22/23` 保持独立，只需统一命名边界（`executor_kind` vs `terminal_backend`）；`DHR_24` 推迟到新 P2 plan/policy 稳定后再重审实战剧本。

### P1 · 反方案（codex 首选）
**两层模型**：外层 DAG 编排类型化流程宏，`dev_harness_card@v1` 内部仍做模板等价校验；跨仓/外部走 outbox。
> 只有用户明确要求「任意改变卡内复核/收口顺序」时，才值得做完整 invariant engine；那应视为新的 P2 主架构，而非 B14 小修。

### codex 列出的用户须决定项
编排粒度 / 周报失败是否阻塞 / P2 允许到哪种外部效果 / 两轮复核的「独立」按什么判 / 用户建 run 前确认到什么粒度。

## R2 · claude-grok 评估（第二版：两层模型草案）

### 结论
> **不能整版确认。** 方向（内层冻结 + 版本发布 + 外部效果走 outbox）对；本草案作为可开工方案不通过，卡在**外层授权未闭合（P0）**。

### P0 · 两层模型没有闭合「红线 ≠ 授权」，越权从卡内挪到了卡间
**C3 只管「多写了什么」，不管「少跑了什么」。** 少跑 R1/R2/lesson_review/收口确认**不产生额外写入**，子集关系仍成立。

- snapshot 现役冻结物**不含图拓扑、宏列表、边、触发条件、开关**（`design/02:209-211`、`:274`、`P2 DevPlan:229`）。
- 草案 E3/E4 的方向是「节点不得引用未授权卡 / 每节点须有合法 owner」，**不是**「snapshot 每张卡必须被质量宏覆盖」，也不是「有副作用的宏必须接在质量闸下游」。
- H3 只展示「卡清单 + 宏及版本 + 副作用**摘要**」，比「卡和主题」只多一个集合级摘要，**拓扑仍未授权**。

**具体绕过（按草案现写的 E1–E5 全部能过）**：
1. 用户授权卡 `FOO` + 周报目的地；H3 显示宏集合 `{dev_harness_card@v1, emit_event@v1, archive@v1}`。
2. planner 交图：`emit_event`（`depends_on=[]`）→ `archive`，**卡宏与之并行或根本不实例化**。
3. 副作用仍 ⊆ H3 摘要；E4 只要求已存在节点 owner 合法；无依赖的 `emit_event` 是**第二源点**、不是孤儿——与今日 fixture 节点 E 同形。
4. 周报被更新成「任务完成」，R1/R2/lesson_review/收口确认一次都没跑。

> C7 的 `run:` grant 也没定义签发者、字段、是否默认随建 run 赠送——若建 run 就赠送 `emit_event`，任何跑卡授权都会附带跨仓事件权。

**建议（二选一，否则不得整版确认）**：
- **Playbook（grok 推荐）**：注册 2～3 条已审图，用户在建 run 窗口点选；snapshot 冻 `playbook_id+version+content_hash`；planner 只填槽。**谁授权这张图 = 用户点的那条 playbook。**
- **若坚持自由拼**：snapshot 必须冻结**完整外层图**（节点、边、参数、触发谓词），H3 展示整图而非集合摘要；并加机器闸——任何外部 effect 不得在其 `owner` 卡到达约定终态前变 ready；E3/E4 补「snapshot 卡必须被 `dev_harness_card` 实例覆盖（cancelled-exempt 除外）」反例；C3 改写为「副作用 ⊆ 许可 **且** 必经闸 ⊆ 已发生」。

### P1 · 「宏内部固定」的参数面没划线，E2 不可测且能被参数化掏空
`integration=true` 今天**已经是**改流程的开关（`design/02:166` 棒 7a 整段可消失），而 B14 语义等价**不核开关**（`design/02:274`）；`brief_ref` 今天可指任意文件（`relay-schema.ps1:91-95`）。

grok 给出的划线表：

| 仍算填槽位（v1 允许，值须 ∈ snapshot/注册表允许集） | 算改流程（必须发 @v2） |
|---|---|
| `card_id` / `module_slug`（∈ snapshot） | 增删改**必经**内层节点 |
| `brief_ref`（须是该卡 workspace 的 brief，禁任意路径） | 关掉任一兜底闸（含 lesson_review、R1/R2、8 件套谓词） |
| `profile_id` / `script_spec_id`（∈ 注册表 ∩ snapshot allowlist） | 改必经边、改 `review.md` 合法写者、改 owner、改 effect 集 |
| 宏**已发布**的可选节点开关（v1 仅继承今天的 `integration/e2e`） | 新的可选节点、放宽返工上限、agent↔script 互改 |
| `emit_event` 的目的地/事件类型（∈ snapshot 外部许可） | 计划内联命令（现役已禁，保持） |

建议：params schema 纳入宏 `content_hash`；snapshot 增 `allowed_profiles[]` / `allowed_script_specs[]` / `allowed_destinations[]`；E2 加三条反例（`skip_r1=true`、`brief_ref` 指他卡、注册表挑高权限 script_spec）。

### P1 · E2 与 D4/U4 互斥（草案自相矛盾）
E2 要求 `dev_harness_card@v1` 展开等于今天 11 棒；偏差①要把 R1 塞进施工批次、②要把棒 8 拆成多个独立闸——**都改 11 棒拓扑**。
> 建议：①② **不要进 v1**，登记为 v1 已知债，走 H2 发 `@v2`。这正是两层模型存在的理由。
> ① 的真实成本被低估：节点表的「每批小审」在无常驻主控的 relay 里等于**施工中多次 fresh launch**，不是把棒 4 往前挪一格。

### P1 · 验收盖不住新授权面，多条会被自证循环糊过去（教训库候选-2）
| 缺口 | 为什么会糊 |
|---|---|
| 无「省略闸」反例 | E3/E4/E5 全绿也拦不住「不跑卡宏只发事件」 |
| E2「以 diff 证明断言未放宽」 | 新开测试文件、改 fixture、把现行行为拍成期望，旧文件可一字不改（候选-1） |
| E5 只核「声明 ⊆ snapshot」 | 不核「**实际写入** ⊆ 声明」；声明可以少报。须挂 B9 风格的前后快照 |
| E6「重复消费不产生第二次副作用」 | 无真实消费者只能 mock，等于 outbox 自己证明自己。必须读**周报仓实际 diff**、期望值硬编码 |
| E3 用 `plan-v1-chain.json` 节点 E 做锚 | 合法，但须双解析器：v1 仍接受（否则打穿 E9），v2 外层图才拒 |
| E1 未定义「谁能注册宏」 | 任意 agent 往 `~/.dh-relay/registry/` 写弱闸 `dev_harness_lookalike@v1`，H3 只显示 id |
| H1 依赖未设计的消费链（U2） | H1 留在本增量 = 不可执行 |
| 草案 H1/H2/H3 与 `design/02:284-286` 的 H3/H4/H5 **撞号** | 晋级时会串验收 ID |

建议补：`E-omit`（省略质量宏 / 无前置 emit 各一反例）、`E-cover`（snapshot 卡无 `dev_harness_card` 实例即拒）、`E-actual-effect`（实际路径 ⊆ 声明 ⊆ snapshot，独立 oracle）、`E-register`（只有宿主/用户能注册宏）。E2 除 diff 外加**变异探针**（删 B3 一条合法顺序必须红）。

### P1 · U2 不是产品尾巴，是架构空洞
草案连 **outbox 落在哪都没写**。三种落点各有致命面：`.dh-relay/` 不进 git 对端看不见；`docs/relay/` payload 进源仓历史；`~/.dh-relay/` 仅本机、任何本地进程可伪造。

未登记的新安全边界六条：传输/可见性、消费链独立授权、事件真实性（宿主签名）、payload 完整性、触发谓词（卡终态还是 run 终态、失败发不发）、失败可见性（毒消息/重试耗尽/写冲突谁看）。
> H1 若仍留在本增量，本条**升 P0**。

### P2 · §5 三条偏差：①②成立，③归类错；另有 7 处未登记
独立比对 `节点表.md:14-34`（18 节点）对 `design/02:157-172`（11 棒）：

| 未登记偏差 | 说明 |
|---|---|

## 主会话裁决

**全部采纳，零驳回。** 两轮共 2 条 P0 + 9 条 P1/P2，无一条被判为不成立，也无一条被转成新的产品取舍。

理由：两轮的 P0 都能由主会话独立复核逻辑成立——
- R1 的 P0：模板不只是形状检查，它同时框死动作集合，撤掉后 planner 成为权限授予者。成立。
- R2 的 P0：子集公式对**省略**无解。少跑质量棒不产生额外写入，`⊆` 关系照样成立。成立，且这是 R1 也没抓到的。

主会话另需自认两处：
1. **草案引用 `evidence/04` 但从未落盘**，被 R2 查出「仓内无此文件」——本文即为补录。
