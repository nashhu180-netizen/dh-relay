## 0. 阻塞依赖（**整改后新增，是本设计能否成立的前提**）

**`F-6809`（本文首次登记）：Claude 的 agent 状态会把真实 blocked 误报为 idle（假就绪），使 DHR_68 的两条启动期 blocked 检测同时失效。**

> **【定向复审 V-03 采纳】原表述「DHR_68 只认 `agent_not_ready`」不准确，已改写。** 复审指出现役实现不止一条检测；主控回查代码确认复审是对的。

[evidence/32 §2](../evidence/32-A27-目录信任能力矩阵-实测.md) 实测：Claude 在未信任目录启动时，`herdr agent start` 返回 **exit 0**、`agent get` 返回 **idle**，而屏幕上确实是目录信任框（`pane get` 同时刻为 `blocked`）。

现役 `relay-core/runtime/executors/herdr/herdr-executor.mjs` 有**两条**启动期 blocked 检测，对 Claude **同时失效**：

| # | 检测 | 代码位置 | 对 Codex | 对 Claude |
|---|---|---|---|---|
| 1 | `start.notReady`（`agent_not_ready` 错误码）→ `startBlocked` | `herdr-executor.mjs:73` | 命中 | **不触发**（start 返回 exit 0） |
| 2 | 就绪轮询观测到 `herdr_status === 'blocked'` → `launchBlocked` | `herdr-executor.mjs:99,106` | 命中 | **不触发**——轮询循环的继续条件是 `!['idle','working'].includes(status)`，假 `idle` 使它**立即退出**，`readyObservation.herdr_status` 即为 `idle` |

结果：`launch_blocked = false`、`blind = false`，relay 把一个卡在信任框上的 Claude 当成就绪 agent。

**证据边界（复审 V-03 要求，如实登记）**：evidence/32 同时记录了 `agent get` 与 `pane get` 存在采样时刻不一致的现象，因此**单次观测不足以证明"每次启动必现"**。本 finding 的关闭判据**不是**再观测一次，而是：构造受控回归夹具（`agent get` 返回 `idle` ∧ `pane get` 返回 `blocked`），断言 relay **不发送提交指令**、走人工暂停。

**为什么它阻塞本设计**：路线 A 的失败回退路径就是 DHR_68 的「人工暂停」。若预置失败或被产品回写覆盖，框会照常弹出；此时 relay 对 Claude **认不出 blocked**，会把提交指令发进信任框——**这正是 `A27-M7` 明令禁止的「静默挂死」形态**。

**处置**：`F-6809` 必须**先于**本设计的 B-adjust 单独立卡并收口；本设计的验收项 `A27-M7` 依赖它成立。**不在本设计的允许路径内自行修复。**

## 1. 目标、边界与决定

### 1.1 白话说明：这在解决什么

你派活给 Codex / Claude Code 时，产品自己会弹一个「你信任这个目录里的内容吗」。今天（DHR_68 之后）relay 的行为是：**看见了、记一条"在等你"、停下来等你去按**。你要的是：**别停，直接替我按"信任"。**

**裁定后的实际做法**（路线 A）：relay 不去按那个框，而是**在启动 agent 之前，先把目标目录写进产品自己的信任名单**，让框根本不出现。

做完之后你手里有什么：新目录第一次派活不用再去点那一下；每次自动放行都有一条可查的账；出问题有一个总开关能关掉，关掉后行为退回 DHR_68 的人工暂停。

### 1.2 这道闸实际拦的是什么（事实登记 · 已按 R-09 补证据边界）

产品问的虽然是"目录"，但答"信任"之后放开的是**该目录内自带的 agent 配置对 agent 的指挥权**。

| 产品 | 本机实测版本 | 目录信任放开的项 | 证据边界 |
|---|---|---|---|
| Claude Code | v2.1.251（[evidence/32](../evidence/32-A27-目录信任能力矩阵-实测.md) 实测） | `.claude/settings.json`（其中 **hooks 以当前用户权限执行命令**）、`CLAUDE.md`、项目级 MCP 声明（文件名是 **`.mcp.json`**，不是 `settings.json` 内的字段） | 依产品公开文档 + 本机版本；**未逐项在本机实测**，不声称已穷尽 |
| Codex | v0.151.0（[evidence/32](../evidence/32-A27-目录信任能力矩阵-实测.md) 实测；信任框原文自述 "allows project-local config, hooks, and exec policies to load"） | `.codex/config.toml`、`AGENTS.md`、项目级 exec policy | 同上；**未逐项在本机实测**，不声称已穷尽 |

> R-09 采纳记录：原草案把 Claude 的项目级 MCP 写成 `settings.json` 的一部分（错，应为 `.mcp.json`）、未写明 hooks 以用户权限执行命令、Codex 侧未挂本机版本证据。以上均已修正，并显式标注"未穷尽"。

所以「自动信任任何目录」在语义上等于：**relay 替你预先同意"它拿到的任何仓库，都可以指挥 agent，包括跑命令"。**

这与用户「目录是用户自己开的」的前提**部分成立、部分不成立**：今天路径确实由用户手打；但 `AGENTS.md` 冻结的产品定位是「relay 是给**任意业务仓**用的通用工具，它操作的一直是**别人的仓**」，到 P7 跑真实任务卡时 `work_dir_root` 来自 RelayPlan / 项目注册表，不必然是用户刚点开的那个。**本条只作事实登记，不改变用户裁决。**

### 1.3 冻结决定（来自用户对话裁决）

1. **授权范围 = 任何目录**。不做路径白名单、不限于 relay 自建的临时 fixture 根、不区分仓内仓外。用户明文裁决，已知代价见 §1.2。
2. **审计保留**。每次自动放行必须留下可查的结构化记录。用户未反对；理由是它不牺牲任何便利。
3. **撤销保留**。必须有一个总开关能关掉自动放行；关掉后行为**逐字**退回 DHR_68 的「一次持久 Attention + 人工确认」。用户未反对；同上。
4. **只放行"目录信任"这一类框**。工具执行审批、权限升级、危险命令确认、账号/登录相关的任何对话框，**一律不代答**，继续走人工暂停。这是本设计的硬边界，不随 §1.3.1 放宽。（用户理解对齐时明确：「产品弹的**所有目录**都信任」——限定词是"目录"，不是"所有框"。）
   > **路线 A 下这条被结构性满足**：机制是"预置目标目录的信任条目"，它在物理上**不可能**触碰任何其它类型的框——不发任何按键。R-01 / R-02 / R-06 / R-07 所针对的"认错框、按错键"风险因此**不存在于 relay 的执行路径上**；但**预置失败时框仍会出现，由人处理**（【V-06 采纳】不得写成"整类风险消失"）。
5. **覆盖时点 = 会话全程，不限启动期**（**目标不变；路线 A 下的实现形态与实测覆盖面见下**）。
   - **目标**：产品在任何时刻弹目录信任框都不该让人去按。
   - **路线 A 的机制**：在 launch 前预置**目标 git 项目根**（无 git 时为 `cwd`）的信任条目。
   - **实测覆盖面**（[evidence/32 §1、§3](../evidence/32-A27-目录信任能力矩阵-实测.md)）：信任以 **git 项目根**为单位 → 目标仓的任意子目录随之覆盖；**worktree 继承主仓信任** → 一卡一树无需额外预置；Claude 会话中途 `/add-dir` 未信任目录**不过信任闸**（部分测得，有 auto mode 混淆项）。
   - **未覆盖的残余情形**（如实登记，**不得声称已覆盖**）：agent 在会话中途进入一个**未预置的嵌套 git 仓**并触发新的信任框——本轮**未实测**该场景会不会真的弹框（中途不重启进程，主控推断不会，**这是推断不是实测**）；以及未来产品版本改变信任粒度。
   - **残余情形的行为**：**回落 DHR_68 的人工暂停**（不代答、不按键）。
   - **【定向复审 V-04 采纳】该回退不得只由人验背书。** 复审指出：`F-6809` 已证明 Claude 的状态观测可能漏报，而 `A27-H4` 只是人判体验，**证不了"不会把后续指令打进框里"**。故新增机器项 `A27-M11`（§4.1）：构造"已启动后进入未预置嵌套仓、两产品分别模拟真 `blocked` 与状态错报"的夹具，断言**零按键、零提交指令、恰一条持久 Attention**。
   - 因此 §1.3.5 的承诺整改为：**「目标是全程免按；机制上由 git 根粒度覆盖实测到的全部情形；剩余情形安全回退，绝不静默继续」**，而不是无条件的"全程覆盖"。
   > 这是相对原冻结文本的**收窄**，因为原文的无条件承诺在路线 A 下不可证。
   >
   > **【理解对齐已完成 · 用户 2026-08-31 明文确认】** 主控向用户复述本条收窄并给出三个选项，用户选择「**停下来等我按**」——即：未覆盖到的那一格，relay **退回 DHR_68 的人工暂停**（记一条持久 Attention、扣住提交指令、等用户按完再发），**不叠加路线 B 代答**。用户同时接受"极少数情况下仍要按一次"这个代价。记录见 [31 §10](../evidence/31-A27-目录信任自动放行-交叉审核记录.md#understanding-a27)。
6. **DHR_68 的安全暂停路径不下线**，它是本机制的兜底与回退目标。**其对 Claude 的失效见 §0，必须先修。**

### 1.4 非目标（**已按 R-11 修正自相矛盾**）

- 不读取、不上传、不记录任何凭据、token、cookie、账号状态。
- 不代做除目录信任外的任何产品审批（见 §1.3.4）。
- **不代答任何框**（路线 A 裁定后新增：本设计不发送任何按键）。
- 不改 Receipt / Result / **driver 的 Result 判定**语义。
- **【R-11 修正】** 原文写「不改 contracts / Store」是**自相矛盾**：新增审计事件种类必然要动 `relay.event/v2` 的**事件种类闭集**，及其 Store 写入、read-model 投影与 `inspect` 消费面。**正确表述**：本设计**允许且仅允许**在 `relay.event/v2` 闭集中新增审计事件种类及其配套投影/消费改动（精确落点在 §6 冻结），**不改任何既有事件种类的字段与语义**，不改 RPC 面。
- 不新增网络端口、跨主机授权、自动登录。
- 不承诺覆盖未来任意产品版本的 UI 变化（不可证，见 §5 反例）。
- 不碰 Linux / SSH（仍按 `B-22` ① 延后）。

## 2. 机制

产品不提供绕过该框的命令行参数——[evidence/32 §1 C-4](../evidence/32-A27-目录信任能力矩阵-实测.md) 已用本机可得的**最强旁路参数**复证：本机 `codex` 是固定注入 `--dangerously-bypass-approvals-and-sandbox` 的壳，信任框**照弹**；DHR_35 亦已实测 `--sandbox` / `--ask-for-approval` 不绕过，`backlog DHR-BL-2` 记载 `--dangerously-skip-permissions` **不覆盖**该框。故只剩下面两条路。

### 路线 A · 启动前幂等预置（写产品自己的信任表）—— **已裁定采用**

launch 前把**目标 git 项目根**（无 git 时为 `cwd`）写进该 profile 的产品配置：Claude 是 `~/.claude*.json` 的 `projects["<path>"].hasTrustDialogAccepted=true`；Codex 是 `~/.codex/` 下的等价项（**格式未实测，本草案不假设，见 §2.2 前置**）。

- **已知可行性**：`backlog DHR-BL-2` 记载 2026-08-16 DHR_04 首跑时，主控手工往三份 `.claude.json` 写该字段后配一次 `send-keys Enter` 解开，**后续两棒未再撞**。
- **优点**：框根本不出现；**零按键**；无屏幕解析、无按键落错的可能；可直接断言"配置里有这条"，机器证干净。
- **代价（全部保留，不因裁定而弱化）**：
  1. **要写用户级产品配置**——`B-22` ② 明确"禁止读取/写入产品配置值"。**用户已于 2026-08-31 明文松绑**（见 §7）。
  2. **格式是产品私有、无文档、随版本变**；**Codex 侧格式至今未实测**。
  3. **并发回写危险**——`DHR-BL-2` 已记载 CLI 退出时会回写同一份 `.claude.json`，预置必须幂等、可重入且**容忍被覆盖**。**写坏用户配置是本路线的一票否决项。**

### 路线 B · 观测到 blocked 后代答（不碰任何配置）—— **未采用，保留作形成史与回退参考**

复用 DHR_68 的 `launch_blocked` 缝：观测到 `blocked` → 读 pane 文本 → 匹配已登记的信任框特征 → 导航到肯定项 → 发回车。

- **优点**：一个字节的产品配置都不碰。
- **致命代价（审核 R-01 的核心结论）**：herdr **不提供对话框身份**——`AgentStatus` 只有 `idle/working/blocked/done/unknown` 五值，`agent read --source detection` 实测只是另一份屏幕文本，事件闭集里没有任何"对话框/审批"事件（[31 §6.1](../evidence/31-A27-目录信任自动放行-交叉审核记录.md)）。存在进程级 provenance（`pane process-info` 给出不可由 pane 输出伪造的 `pid` / `argv` / 实时 `cwd`），能把风险压窄到"同产品同目录下的框间混淆"，但**不能消除**它（[31 §6.3](../evidence/31-A27-目录信任自动放行-交叉审核记录.md)）。
- **实测出的一条会致命的细节**（[evidence/32 §4-B](../evidence/32-A27-目录信任能力矩阵-实测.md)）：**各框的默认高亮项方向相反**——Claude 信任框默认落在 `No, exit`，Claude 命令审批框默认落在 `1. Yes`，Codex 信任框默认落在 `1. Yes, continue`。任何"盲按回车"实现会在 Claude 信任框上**退出会话**、在 Claude 命令审批框上**批准任意命令**。
- **若将来重启路线 B**，以下护栏是硬前置，不得简化：fail-closed 匹配（只有命中已登记信任框特征才动作，其余零按键）；**禁止盲发回车**，必须解析选中标记、导航到肯定项、复验当前选中项后才发键；单 Attempt 放行次数上限；matcher 为代码内版本化闭集 + hash，增改走新的 A-full（R-06）。

### 2.1 D-1 终裁：**路线 A 单用**

<!-- dh:decided:v1 id=A27-D1 by=user at=2026-08-31 choice=route-a -->

**用户 2026-08-31 对话明文「同意 A」，追问后再次明文「同意 A」。**

裁定理由（以实测为准，非偏好）：

1. **在预置成功的路径上，relay 不再有"认框 / 按键误答"风险**——框不出现，relay 也一个键都不发，审核 R-01 判定本设计不通过的**根因**由此结构性消失。
   > **【定向复审 V-06 采纳】原文写「消灭整类风险」少了条件。** 路线 A 消灭的是 **relay 的屏幕匹配与代答误答**风险，**不是**消灭目录信任框本身：**预置失败时框照常出现，由人处理**（DHR_68 人工暂停）。全文不得出现无条件的"消灭"表述。

### 3.2 撤销（总开关）

- 单一 relay 级开关，关闭后**零预置、零按键**，行为与 DHR_68 完全一致。
- **默认值 = 开**（D-2 终裁 = ① 全局默认开，无任何作用域限制）。
- 关闭为**即时生效**：已在跑的 Attempt 不追溯，但其后的每一次放行判断都读当前值。
- **【R-02 / R-07 采纳】串行决策语义**：单 owner 串行执行「解析目标目录 → 读开关 → 预置 → 复读验证 → 写审计」，**每一步之前重读开关**；中途关闭则**立即停止且不留半状态**（已写入的条目不回滚，但必须如实写 `outcome`、`permit_epoch` 与 `cancelled_at_stage`，不得静默继续后续步骤）。
- **【V-01 采纳】开关的线性化语义必须显式定义，不得只靠"每步重读"**：
  - 开关取值有**单调递增的 epoch 来源**（关闭 / 打开各推进一代）；
  - 定义**线性化点** = 执行写入前最后一次读开关的时刻；写入必须与该次读取**原子关联**（CAS 或 owner 队列序号），审计记的 `permit_epoch` 就是它；
  - **关闭操作的保证边界**须写明：关闭返回后，保证不再有**新**的写入被许可；已进入写入的那一次是否完成，由 `permit_epoch` + `cancelled_at_stage` 事后可判，**不承诺回滚**。
- **该开关是本设计唯一的收敛手段**（D-2 选 ① 后作用域限制取消），其正确性为**关键安全控制**，不可降级、不可简化。

### 4.3 必须覆盖的变异与负例（R-10 采纳）

- 产品配置文件**不存在 / 为空 / 手工改坏 / 权限只读**；
- 预置写入后，模拟 **CLI 退出回写**把条目抹掉 → 必须被复读发现并回落；
- 同一 Attempt 内**重复 poll**触发重复预置 → 去重键生效、只写一条审计；
- **开关在两步之间被关掉** → 立即停止且如实记 `permit_epoch` 与 `cancelled_at_stage`；
- 目标目录是**嵌套仓 / worktree / 无 git 的裸目录**（evidence/32 六形态）；
- **产品改字段名**（构造未知格式）→ 回落人工暂停而非静默继续；
- **读—改—写之间的外部更新**：relay 读取后、发布前，由产品或用户写入无关字段 → 断言该字段保留（V-05）；
- **两个不同目录并发预置** → 断言互不覆盖（V-05）；
- **路径别名与规范化**：大小写、尾斜杠、相对路径、8.3 短名、junction / 符号链接、UNC 与盘符混用（V-08）；
- **逐步翻转总开关**：在解析后 / 读开关后 / 写入前 / 复读前各翻转一次 → 断言可从审计重建决定过程（V-01）；
- **中途进入未预置嵌套仓** × {真 `blocked`、`F-6809` 形态的假 `idle`}（V-04）；
- **recovery 路径**上的同一组用例。
