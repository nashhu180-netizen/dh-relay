## 1. fresh 只读审核与裁决

- 触发原因：DHR_34 开工预审发现 launch receipt 不是 Attempt 身份链、DHR_34 无权扩 contracts，且现役状态无 `paused` 枚举。
- 审核形态：Herdr 管理 pane 内的 fresh 只读 Codex reviewer；终端启动屏显示 `gpt-5.6-terra high`，实例自报模型身份为 `Codex（GPT-5）`。不将该自报升级为更精确的部署身份断言。
- 审核迭代：先后收敛 canonical event detail、pause/retry 幂等、fence/Attention 重放、显式人工 profile 选择、v1/v2 兼容、崩溃恢复 journal、payload 4KB 上界与 Receipt fallback snapshot。最终 targeted 文本复核结论：`P0=0, P1=0, P2=0, P3=0, PASS`；局限是尚未实施，强杀恢复与兼容测试属于后续前置契约卡验收。

主会话裁决：全部采纳审核要求。正式输入冻结以下边界：

1. 使用 Attempt Receipt 而非 launch receipt 承载身份与有序 fallback snapshot；
2. 无自动 fallback 以既有 `waiting_human/needs_you` 表达“已暂停等待处理”，并以单条 canonical event 原子导出 fence 与 Attention；
3. 人工只能从冻结、脱敏的预登记 profile 中显式选择 `retry-with-profile`，旧 Attempt 永久 fenced；
4. 旧 RPC v1 endpoint/字节形态保持兼容；新能力通过独立 bootstrap/v2 endpoint 协商；
5. 多文件 mutation 的 blob-before-prepared durable 顺序、重放和 fail-closed 规则必须由前置契约卡实现并强杀验证。

## 2. 讲解、理解与整版确认
