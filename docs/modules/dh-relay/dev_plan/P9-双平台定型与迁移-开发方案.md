## 0. 定位

P9 负责把已经证明可用的 DSH + Relay + Herdr 路线定型为 Windows 与 Linux 都可维护的个人工作台，并完成旧实现和并行项目的处置。

P9 不重新发明流水。它处理跨平台差异、版本升级、安装发布、遗留数据、agent-console 决策和长期运行边界。

## 1. 前置条件

- P8 Gate 通过；
- 真实多卡 Run、重编排、诊断、Outbox 和归档已完成；
- 用户确认该工作台具有日常使用价值；
- 用户明确放行 P9。

## 2. 交付范围

交付：

1. Windows 与 Linux 的安装、启动、IPC、Herdr 和 Git 行为对齐。
2. 至少跨一个 DSH 版本的兼容升级验证。
3. Profile、Bundle 和 Relay Runtime 的可重复发布方式。
4. v1/P1 历史现场与新 v2 Run 的发现和只读策略。
5. psmuxlegacy、旧 PowerShell Core、P2/P3 的最终归档说明。
6. agent-console 的最终处置。
7. 一份架构定型 ADR 和运行手册。

不交付：

- 多机分布式调度；
- 云端 Relay 服务；
- 任意 DAG 市场；
- 自动安装未知第三方插件；
- deploy 和生产环境控制；
- 跨仓 Run。

### DHR_46：Linux 全链与能力矩阵

目标：

- 在 Linux 上安装同一 Personal Workbench Profile。
- 使用 Unix Domain Socket 连接 Relay Runtime。
- 验证 Herdr、Process、Git、路径、文件权限和进程树清理。
- 跑一条 basic-agent-task 和一条代表性 DevHarness 路径。

能力矩阵至少覆盖：

```text
DSH 安装与 Web UI
树外 Host/Client Plugin
Relay Runtime
IPC
Herdr launch/observe/focus/stop
Codex/Claude Code 可用入口
Git worktree/finalizer/archive
截图或等价证据
权限证明
重启恢复
```

强证据能力缺失时必须明确拒绝相应 Workflow，而不能静默降级。

### DHR_47：升级、发布与 legacy

DSH 升级：

- 从 Pilot 锁定版本升级到一个后续版本。
- 记录 Bridge 兼容层改动。
- Relay 协议和 Run Store 不随 DSH 私有类型变化。
- 升级失败可以回滚 Profile，不影响既有 Run。

发布方式：

```text
预构建 npm/tarball Bundle
Relay Runtime 的可校验发布物
独立 DSH Home 初始化脚本
版本清单与 checksum
```

供应链规则：

- 不允许模型自动批准未知 Git 包的 prepare。
- 插件来源固定版本或 commit。
- 凭据与业务仓内容不进入发布物。

legacy 策略：

- `.dh-runtime/relay/` v1 只读发现和归档，不 resume。
- 旧 PowerShell P1 工具保留到新 Runtime Dogfood 通过。
- psmuxlegacy 只作为受控回退，不被新 Run 默认选择。
- P2/P3 保持冻结说明，旧任务不复活。

### DHR_48：Dogfood 与架构定型

双平台各完成：

- 一条真实 Relay Run；
- DSH 重启和 Runtime 恢复；
- Herdr 外部 Agent 施工；
- Attention 与 Approval；
- docs/relay 归档和 Oracle。

架构 ADR 最终确认：

```text
DSH 是否继续作为唯一工作台
Relay Runtime 最终语言与发布形态
Herdr 的长期主宿主地位
psmuxlegacy 的保留期限
agent-console 的处置
```

agent-console 候选处置：

1. 停止开发并归档。
2. 缩成启动器、托盘和 WebView 壳。
3. 只保留 DSH 故障时的应急只读控制台。

选择依据是实际体验和维护成本，不按既有投入做沉没成本决策。

## 4. P9 最终闸

### 机器闸 P9-M

| ID | 命题 |
|---|---|
| P9-M1 | Windows 与 Linux 均能安装、连接和运行 |
| P9-M2 | 两平台的强制权限、进程清理和恢复行为有证据 |
| P9-M3 | 跨一个 DSH 版本后，改动集中在兼容层 |
| P9-M4 | Relay Store、协议和业务仓真相不受 DSH 升级污染 |
| P9-M5 | 发布物可重复构建并有版本、checksum 和回滚路径 |
| P9-M6 | legacy v1 和 psmux 路径不会被新 Run 误用 |
| P9-M7 | 双平台真实 Run 的外部 Oracle 均通过 |

### 人类闸 P9-H

用户最终判断：

- DSH 工作台是否成为日常默认入口；
- Windows 与 Linux 的操作差异是否可接受；
- 启动、升级和故障恢复是否足够简单；
- agent-console 是否仍有独立存在价值。

## 5. 完成定义

```text

```

04、旧 P2、旧 P3 和 Pilot 证据继续保留为历史与决策依据，不再与现役架构并列。
