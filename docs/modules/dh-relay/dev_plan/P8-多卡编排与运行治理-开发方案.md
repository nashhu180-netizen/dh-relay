## 0. B 方案审核与理解确认

### 0.1 白话说明：这个阶段做啥、解决啥、做完得到啥

- **要解决的问题**：P7 只跑一张卡。真实工作是多张卡有依赖、要并行、中途会卡住需要重排或诊断、完成后要写周报归档。P8 让内核能同时管 2~3 张卡，并把「卡住怎么办」变成有据可查的治理动作，最后用一个独立的「外部审计员」重算一遍确认没作弊。

| 任务 | 用大白话说在做啥 | 解决什么问题 |
|---|---|---|
| DHR_41 | 一次运行装 2~3 张卡：有依赖的按顺序、改同一批文件的强制串行、互不相干的并行；同一个仓库同一时刻只允许一个合入动作 | 多卡并行不打架、不冲突合入 |
| DHR_42 | 卡内最小重排：某卡因依赖阻塞时，AI 重编排师只能在当前卡内新增合法前置步骤，生成一份规范的「计划变更差异」给你批准；不许加卡、换卡、改目标 | 卡住能自救，但改动范围被锁死、必须你点头 |
| DHR_43 | 诊断两段式：只读诊断 AI 出报告和选项后退出；内核持久保存待处理提醒，你稍后从任何客户端选一个选项 | 诊断不会偷偷动手，你不在线也不丢事 |
| DHR_44 | 事件钩子 + 可靠出站队列：任务节点完成 / 失败 / 需要注意时自动触发动作，首个真实动作是往周报里追加进度；DSH 不开也照常发，失败可查可重试 | 治理动作自动化且不丢 |
| DHR_45 | 归档 + 外部审计：每次运行的结果写进业务仓 `docs/relay/`；一个不依赖内核代码的 Oracle 独立重算 verify、状态、清理、幂等等是否一致；用你选的 2~3 张真实卡实战一遍 | 内核说的「完成」有第三方核对，不是自说自话 |

- **完成后你手里有什么**：
  1. 接力内核能同时编排多张真实任务卡。
  2. 卡住时的重排 / 诊断 / 待处理提醒 / 批准，全部有持久记录、任何客户端可处理。
  3. 周报自动追加、运行结果自动归档。
  4. 一套独立审计工具，能证明内核没有作弊。

## 1. 概述

- **交付什么 / 不含什么**：
  - 交付：①一 Run 2~3 卡的依赖、并行与路径重叠调度；②同仓 Finalizer 串行与基线刷新；③卡内最小重编排与计划 Revision；④规范 JSON/text Replan Diff（DSH 图形 Diff 为增强渲染）；⑤只读诊断 Agent、持久 Attention 与受控选项；⑥CLI / Pi / DSH 共用的 Attention / Approval 控制合同；⑦Hook、Action Registry 与 durable Outbox；⑧周报进行中与完成后写入场景；⑨run 级 `docs/relay/` 归档；⑩不 import Relay Core 的宿主外 Oracle；⑪DSH 关闭状态下完成一次多卡治理实战。
  - 不含：任意 DAG 编辑器、跨仓 Run、自动修改 DevPlan 目标与验收、模型任意控制事件、外部消息队列、远端部署、多主机分布式调度、Linux 最终发布定型、依赖某一 UI 才能理解或批准的治理对象。
- **承接设计**（拆计划输入 = `design/README.md` 白名单）：
  - [design/06](../design/06-多控制面与Headless-SSH运行-设计补充.md) · 「验收命题」节 **H3 / H5 / H8 / H11**（主承接）以及 **H1 / H2 / H4 的多卡子集**（DSH 未运行时 Outbox 消费与 CLI 治理 / CLI 展示并行·冻结·锁 / 客户端离线不影响调度）+ §6 Headless 下的人机交互与 Approval、§10「P8」。
  - [design/05](../design/05-DeepSeek-Harness插件化与专属工作台-可行性评估.md) · §11 重编排 Agent、§12 诊断 Agent、§13 Hook、Action 与 Outbox、§10.4 Git 留档。
  - [design/02](../design/02-完整流水-产品设计与验收.md) · **B12**（多卡调度、重编排影响面、基线刷新）、**B15**（诊断 Agent 可信只读承载与控制事件权限边界）、**B10**（自举 oracle 宿主外重算、`docs/relay` 归档幂等）、**B9 ②③**（业务仓内容策略与落点纪律 D21）、**B5**（quota 无 fallback → paused → 诊断）；人验 **H3 / H4**（自举跑 2~3 张真实卡、与常驻主控对照）——作为契约 Oracle。
- **前置条件**：active P7 Gate（`P7-M10~M17` 全部通过 + `H1~H10` 用户签收 + 用户明确放行 P8）通过；至少一张真实标准卡在 DSH 关闭路径下完整 verify；单卡恢复、E11、Finalizer、CLI 与 DevHarness Gate 稳定；用户在开工阶段选择 2~3 张代表性真实卡与周报目标项目。
- **实施策略一句话**：不建任意 DAG——卡间边只来自 DevPlan 依赖、冻结的路径重叠规则与发布版 Workflow Contract；每类治理对象先冻结 JSON/text 协议再做渲染，最后用宿主外 Oracle 独立重算真实三卡 Run。
- **任务前缀 / 模块 slug**：`DHR_` / `dh-relay`。
- **批次**：批次 1=`DHR_41`（多卡调度）；批次 2=`DHR_42 → DHR_43`（重编排 + 诊断）；批次 3=`DHR_44 → DHR_45`（Outbox + 归档 / Oracle / 三卡实战，第一个端到端 demo 在 DHR_45）。

| 路径 | 禁改 / 扩展 / 新建 | 说明 |

### 2.3 阶段专属约束

- **P8 正式冻结协议**：`relay.plan-revision/v1`、`relay.replan-diff/v1`、`relay.diagnosis/v1`、`relay.attention/v1`、`relay.control-option/v1`、`relay.control-receipt/v1`、`relay.action-request/v1`、`relay.action-result/v1`、`relay.archive-summary/v1`。
- **CLI 至少补齐**：`relay attention list`、`relay attention show <id>`、`relay attention answer <id> --option <option_id>`、`relay plan show <run_id>`、`relay plan diff <run_id> <revision_id>`、`relay plan approve <revision_id>`、`relay action list <run_id>`、`relay action retry <action_id>`；高权限命令仍由 Relay 校验 Authority 与请求绑定，CLI 命令本身不构成授权。
- **Canonical Replan Diff 至少含**：`base_plan_hash / proposed_plan_hash / added_nodes / removed_nodes / added_edges / removed_edges / affected_cards / frozen_dependency_closure / effect_delta / required_approval`。
- **诊断触发**：`interrupted_unknown`、`paused`、`closeout_blocked`、quota 无 fallback、恢复发现断棒、authority 或 gate 冲突、`executor_lost`。每个选项冻结 `option_id / action / params / target / expected_state_hash / nonce / expires_at`。
- **首批 Hook 事件**：`run.started / node.succeeded / card.succeeded / card.failed / attention.opened / run.finished`。Action 默认 best_effort，不把周报结果冒充源卡验收。
- **归档 Archive 节点**：自建暂存分支、持同仓 Finalizer 锁与 Archive lease、README 按 run_id 幂等 upsert、生成 archive-manifest、CAS 快进后清理暂存分支。

### 3.2 任务卡

#### DHR_41

- **目标**：一 Run 实例化 2~3 张授权卡，卡间边来自 DevPlan 依赖，静态变更范围重叠的卡强制串行，无依赖无重叠的卡按 `max_parallel_cards` 并行；同仓同一时刻只有一个 Finalizer；客户端断开时调度继续，Attention 卡只冻结其依赖闭包；前卡快进后后卡候选在暂存分支 rebase——patch 不变只重确认，patch 变重跑受影响机器闸与两轮复核后重确认，冲突进 `closeout_blocked`。
- **非目标**：不做重编排（DHR_42）；不做跨仓 Run；不做任意 DAG。
- **验收口径**：
  - **机器证**：[design/02 B12](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏) · 本计划 P8-M1/M2：三卡按依赖串 / 并行；重叠卡强制串行；同仓 Finalizer 串行锁生效；基线刷新三分支（不变重确认 / 变重跑 / 冲突 `closeout_blocked`）各有用例；escalate 只冻结依赖卡；cancel_card 不影响其它卡。
  - **机器证**：[design/06 H4 / H5](../design/06-多控制面与Headless-SSH运行-设计补充.md#11-验收命题)：客户端离线不影响调度；Attention 卡只冻结依赖闭包，其余继续。
  - **机器证**：[design/06 H2](../design/06-多控制面与Headless-SSH运行-设计补充.md#11-验收命题)：CLI `relay status / inspect / events --follow` 正确展示并行、冻结与 Finalizer 锁。
- **变更范围**：Runtime `scheduler/`、Finalizer 锁与基线刷新；本卡 `workspace/DHR_41/`（拆卡后各自）。
- **档位**：标准（多卡状态机 + Finalizer 接线；预计拆卡）。
- **实施提示**：复用 P7 单卡 Finalizer 不另写；卡间边只三种来源；先 fake 回放再真实临时 Git 仓三卡剧本。

#### DHR_42

- **目标**：`dependency_blocked` 触发 replan request → replanner profile 只读 Authority / Contract / 当前计划 / 证据 → proposal → Compiler 校验 → Relay 生成 canonical Replan Diff → DSH / Pi / CLI 渲染同一 Diff → 用户批准或拒绝 → Relay 保存 receipt 并发布新 revision；只允许在当前卡内新增合法前置节点，不加卡、不换卡、不删硬节点、不改目标 / 验收 / 外部 effect；依赖闭包在安全点冻结。
- **非目标**：不做跨卡重编排；不做 DAG 编辑器；DSH 图形 Diff 只是渲染器。
- **验收口径**：
  - **机器证**：[design/05 §11 重编排 Agent](../design/05-DeepSeek-Harness插件化与专属工作台-可行性评估.md#11-重编排-agent) + [design/02 B12 重编排影响面](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏) · P8-M3：Replanner 只能提交合法卡内 Proposal，加卡 / 换卡 / 删硬节点 / 改验收各一反例被拒；不受影响卡完成手上节点后继续。
  - **机器证**：[design/06 H3 / H8](../design/06-多控制面与Headless-SSH运行-设计补充.md#11-验收命题) · P8-M4：Replan Diff 有规范 JSON/text 且含 §2.3 全部字段；DSH 不可用时用户可由 CLI `relay plan diff / approve` 完成审批；不同客户端批准同一 revision 的 receipt 语义一致。
  - **机器证**：[design/02 B14 planner 约束](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏)：proposal 与 Authority 语义等价，晋级前 Runner 以 snapshot 复核。
- **变更范围**：Runtime `replan/`、`contracts/`（plan-revision / replan-diff）、`cli/`（plan show/diff/approve）；本卡 `workspace/DHR_42/`。
- **档位**：标准。
- **实施提示**：复用 P1 DHR_02/03 的 blocked → replan → fresh A 回放 Oracle；Diff 先 JSON 后 text，DSH 图形最后。

#### DHR_43

- **目标**：诊断两段——只读 Diagnoser 输出 report / evidence / option set 后退出；Relay 持久化 Attention，任一合法客户端可稍后显示与提交选择；DSH / Pi / CLI 选同一 option 时生成相同语义 Control Receipt；客户端关闭后 Attention 继续存在，无客户端在线时其他无依赖卡继续运行。
- **非目标**：不让 Diagnoser 执行修复；不做通用 Agent 控制事件；不依赖 prompt 声明只读。
- **验收口径**：
  - **机器证**：[design/02 B15 ①~⑤](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏) · P8-M5：option 载荷绑定（换参 / 非声明选项拒）；target + expected_state_hash + nonce 绑定（缺字段 / 旧 generation / 错 run / 重复 nonce 各拒）；单次授权二次调用拒；console 路径另立 schema；Diagnoser 只以 `readonly=true` 且机器可证只读的 Profile 拉起，不支持者拒绝拉起。
  - **机器证**：[design/06 H5 / H8](../design/06-多控制面与Headless-SSH运行-设计补充.md#11-验收命题) · P8-M9：Attention 可跨 DSH / Pi / SSH 断开处理；同一 option 经不同客户端提交生成相同语义 Control Receipt。
  - **机器证**：[design/02 B5](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏)：quota 无 fallback → paused → 诊断被拉起。
  - **机器证**：[design/05 §12 诊断 Agent](../design/05-DeepSeek-Harness插件化与专属工作台-可行性评估.md#12-诊断-agent)：§2.3 全部触发场景各有用例。
- **变更范围**：Runtime `diagnosis/`、`attention/`、`contracts/`（diagnosis / attention / control-option / control-receipt）、`cli/`（attention list/show/answer）；本卡 `workspace/DHR_43/`。
- **档位**：标准（权限边界红线相邻）。
- **实施提示**：只读靠 P6 注册表能力位；Attention 是持久对象不是会话；option 冻结字段全量含 nonce / expires_at。

#### DHR_44

- **目标**：首批事件 Hook（`run.started / node.succeeded / card.succeeded / card.failed / attention.opened / run.finished`）、Action Registry（版本 + content hash）、durable Outbox；首个真实 Action `project-status.weekly-report.append@1`：S3 某批完成后写进行中周报、卡完成后写完成周报；request 不可变并带 idempotency key；DSH 未运行时 Outbox 仍自动消费；CLI 可看失败 / dead-letter 并提交允许的重试。
- **非目标**：不接外部消息队列；不做远端部署；不把周报结果冒充源卡验收；不允许内联 shell 与任意脚本路径。
- **验收口径**：
  - **机器证**：[design/05 §13 Hook、Action 与 Outbox](../design/05-DeepSeek-Harness插件化与专属工作台-可行性评估.md#13-hookaction-与-outbox) · P8-M6：Action 必须已注册并带版本与 content hash；request 不可变 + idempotency key；状态五态；默认 best_effort；DSH 关闭时仍执行；失败与 dead-letter 可见；重试请求经 Relay 校验。
  - **机器证**：[design/06 H1 / H2](../design/06-多控制面与Headless-SSH运行-设计补充.md#11-验收命题)：DSH 未运行时 Outbox 自动消费并记录；CLI `relay action list / retry` 可用。
  - **机器证**：目标项目的业务写入程序与检查器证明周报幂等（重复触发不产生第二条）。
- **变更范围**：Runtime `hooks/`、`outbox/`、`contracts/`（action-request / action-result）、`cli/`（action）、目标项目写入程序（用户确认的项目）；本卡 `workspace/DHR_44/`（拆卡后各自）。
- **档位**：标准（跨项目写入，外部写入权限由用户另行确认；预计拆卡）。
- **实施提示**：目标项目拥有写入程序，Relay 只投递；周报是 best_effort，不阻断源卡；先 fake Action 再真实周报。

#### DHR_45

- **非目标**：不做跨仓 Run；不另跑第二份流程拼结论；Oracle 不 import Relay 生产代码。
- **验收口径**：
  - **机器证**：[design/02 B10](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏) · P8-M7/M8：docs/relay 归档单写、按 run_id 幂等（重复归档反例）、与事件账一致；`archive-manifest` 路径集与各卡 release manifest 路径集不相交；`archive_blocked` 时 run 未标 done；外部 Oracle 对真实三卡 Run 独立重算通过。
  - **机器证**：[design/02 B9 ②③](../design/02-完整流水-产品设计与验收.md#61-ai-自动验收栏)：业务仓内容写入 ⊆ 白名单；非规范落点反例失败、合法同名目录不误杀。
  - **机器证**：[design/06 H3 / H1 / H2](../design/06-多控制面与Headless-SSH运行-设计补充.md#11-验收命题)（H9 归 P9 DHR_46）· P8-M9：DSH / Pi / CLI 对同一治理对象读取相同 Read Model 与终态；DSH 关闭时 CLI 完成一轮 replan 或 diagnosis 选择。

- **变更范围**：Runtime `archive/`、`contracts/`（archive-summary）、`oracle/`、`workspace/DHR_45/evidence/`。
- **档位**：标准（业务仓 git 写入 + 宿主外 Oracle + 真实三卡人判；高危）。
