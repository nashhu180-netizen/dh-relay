## 0. B 方案审核、理解与确认

### 0.1 这阶段交付什么

P8 把 P7 的通用合同用于真实多任务和跨项目运行：一份 RelayPlan 可引用多个 DevPlan 任务；一个任务失败只冻结受影响闭包；三轮未闭合时 fresh Decision Executor 给建议并关闭，编排 Agent在外部完成 B-adjust，再决定拆出的任务是否加入当前 Plan。

| 任务 | 唯一承接 | 明确不做 |
|---|---|---|
| DHR_41 | 2~3 个跨项目 TaskRef 的 registry/binding、显式依赖、并行、共享消费者、workspace/权限/Finalizer 隔离 | 路径重叠或容量互斥不自动变业务依赖 |
| DHR_42 | 编排 Agent驱动的确定性 Plan change、逐项目 receipt 校验、canonical diff、generation activation | 不执行业务 B-adjust、不自动 launch、不设第二 Plan 发布者 |
| DHR_43 | fresh Decision/diagnostic Executor、durable Attention/Result/Handoff、关闭释放与无关 Ready 继续 | 不新增第四逻辑角色，不让 Decision 改计划 |
| DHR_44 | 已取消：历史 Hook/Outbox/周报/业务仓 `docs/relay` | 未来需要时重新走 A-full + B-adjust |
| DHR_45 | PlanHome archive/run summary、宿主外 Oracle、真实跨项目 2~3 TaskRef E2E | 不写业务仓 `docs/relay`，不依赖 Hook/Outbox/周报 |

### 2.1 影响闭包

`affected closure = 问题 seed + 显式 depends_on 下游 + 消费任一受影响输入的共享消费者`。路径重叠和容量互斥只限制同时 launch，不自动形成业务依赖。一个项目失败只冻结该闭包；其他 active/Ready 节点保持状态并可由显式 `continue` 推进。

### 2.2 Decision、B-adjust、Plan 与启动的四步边界

1. fresh Decision Executor 只产出绑定 `subject_task_refs[]`/set digest/candidate revision 的 durable Result/Handoff，并在 Monitor Report durable 后关闭释放。
2. 编排 Agent取得涉及项目的 Authority，在各项目外部 DevHarness 执行 B-adjust；每项目产生独立 durable receipt/result。
3. **加入当前 Plan**：编排 Agent调用确定性命令校验 receipt/Authority/CAS，追加 TaskRef/Node/未启动 supersede 并激活一个 generation。**不加入**：当前 Plan 只登记外部处置引用，`plan_id + generation`、TaskRef/Node 图和 Run 身份不变；新任务留在外部 DevPlan，供其他 RelayPlan/Run 以后承接，本次不自动创建或切换。
4. 另一次显式 `continue` 才可启动节点；activation 本身不 launch。不加入时，编排 Agent可对当前 Run 的无关 Ready 节点发 `continue`。

外部 B-adjust 已成功但 Plan activation 失败时，业务计划保持生效，旧 generation 不变且无 Worker 被启动；修正 Plan change 后以相同 request identity 幂等重试，不跨项目自动回滚。

### 2.3 跨项目边界

- 每个项目独立保留 DevPlan/workspace、canonical repo identity、local binding、Authority、worktree/HEAD、allowed paths、Finalizer、verify 和 release manifest。
- 一个项目的 binding/Authority 不能写另一个项目；一个 Finalizer 不得跨仓持锁或合入。
- Run 汇总逐 TaskRef 标记 succeeded/waiting/failed；总 success 不能掩盖子任务失败。
- PlanHome 保存 tracked Plan/archive 与 ignored runtime/local；业务仓不写 relay 归档副本。

### 3.2 任务卡

#### DHR_41 · 跨项目多 TaskRef 调度与隔离

- **目标**：在同一 Plan/Run 中调度 2~3 个跨项目 TaskRef，校验 project registry/local binding，以显式依赖决定串并行，以共享消费者扩展影响闭包；逐项目隔离 workspace/HEAD/Authority/Finalizer，同仓合入串行，跨项目无依赖 Ready 节点可继续。
- **非目标**：不做 Plan change（DHR_42）；不把路径重叠/容量冲突当业务依赖；不承诺跨仓 Git 原子提交。
- **验收口径**：**机器证**回连 [design/10](../design/10-薄RelayPlan与显式节点边界-产品设计调整.md) `HC-3AT-A32/A34/A38`：task ID 重号、registry/binding 漂移、跨项目借权、错误 workspace/HEAD、一个 Finalizer 管多仓、遗漏共享消费者、全 Run 无差别冻结均拒绝或被独立 Oracle 判错。一个项目失败时另一项目无依赖 Ready 节点可 continue。
- **范围**：`relay-core/scheduler/`、project binding/Finalizer 端口、跨项目 fixtures 与临时 Git 仓测试。
- **档位 / 任务类型**：标准 / 重核。<!-- dh:task-type:v1 task=DHR_41 type=heavy -->

#### DHR_42 · 受控 Plan change 与 generation activation

- **目标**：消费 Decision Result/Handoff 与逐项目外部 B-adjust receipt/result，由编排 Agent选择 TaskRef 加入/不加入；确定性命令校验 Authority、parent digest/CAS/request identity，生成 canonical diff/receipt，加入时追加对象并激活一个 generation，不加入时只登记外部处置引用。
- **非目标**：不执行业务 B-adjust；不让 Decision/Compiler直接发布；不自动 launch；不自动创建/切换其他 Plan/Run。
- **验收口径**：**机器证**回连 design/10 `HC-3AT-A34/A38`：错 receipt/Authority/task-set digest、未生效任务、修改 active/closed、supersede 已启动对象、并发/重放均拒绝；外部 B-adjust 成功但 activation 失败时旧 generation 不变、无新 Pair、同 request 重试不重复建卡。canonical Diff/Receipt 必须展示 TaskRef set、影响闭包、supersede 和 generation。
- **范围**：`relay-core/plan-change/`、`relay-core/contracts/`、workflow/actor 端口与 CLI JSON/text 投影。
- **档位 / 任务类型**：标准 / 重核。<!-- dh:task-type:v1 task=DHR_42 type=heavy -->

#### DHR_43 · fresh Decision Executor 与 Attention

- **目标**：三轮仍未闭合时，为受影响 TaskRef 启动 fresh 只读 Decision/diagnostic Executor；Result/Handoff/Monitor Report durable 后关闭 Ticket、Pair 和终端；持久 Attention 绑定 canonical subject TaskRef set/digest，编排 Agent从任何合法客户端读取建议并执行外部治理。
- **非目标**：不新增 Decision/Diagnoser 逻辑角色；不让 Decision 修改 DevPlan/RelayPlan、执行修复、调用 continue 或自动授权 B-adjust。
- **验收口径**：**机器证**回连 design/10 `HC-3AT-A35/A38`：复用施工/Reviewer会话、缺 fresh/subject set/candidate revision、Result 未 durable 即释放、Decision 越权、Pair 关闭失败却释放容量均拒绝；Decision 合法关闭后无 Worker 存活，无关 Ready 节点状态不变。
- **范围**：`relay-core/decision/`、`relay-core/attention/`、通用 contracts、launcher/recovery/CLI 窄装配。
- **档位 / 任务类型**：标准 / 重核。<!-- dh:task-type:v1 task=DHR_43 type=heavy -->

#### DHR_44 · 已取消的历史卡

- **历史目标**：Hook、durable Outbox、周报 Action 与业务仓 `docs/relay` 归档。
- **取消理由**：这些范围来自已冻结的 design/02、design/05、design/06，不属于当前正式 design/10；不得在本次计划中静默保留或改造成别的任务。
- **恢复条件**：未来若用户仍需要，先以新的 A-full 写入正式设计验收，再单独 B-adjust；DHR_44 ID 不复用。

#### DHR_45 · PlanHome archive、独立 Oracle 与跨项目 E2E

- **目标**：在独立 PlanHome 生成 archive/run summary，逐 TaskRef 保存结果和各项目 receipt/workspace/HEAD/release manifest 指针；用不 import Relay 生产代码的 Oracle 重算 TaskRef set、依赖/影响闭包、generation、部分结果和资源释放；以至少两个项目、2~3 个 TaskRef 实演加入与不加入当前 Plan 两条分支。
- **非目标**：不写业务仓 `docs/relay`；不做 Hook/Outbox/周报；不另跑第二份流程拼结论。
- **验收口径**：**机器证**回连 design/10 `HC-3AT-A32/A34/A38`：archive/run summary 幂等且与事件账一致，各项目 manifest 不混写，总 success 不掩盖失败，错误 binding/HEAD fail-closed，终态资源已释放。**人判**回连 `HC-3AT-H11/H12`：5 分钟内分别演示加入/不加入、activation 与 continue 分层，并从 PlanHome 追到两个 TaskRef 的 registry/binding digest、generation digest、workspace/HEAD 和部分结果。
- **范围**：`relay-core/archive/`、`oracle/`、跨项目 E2E fixtures、CLI 追溯输出与证据目录。
- **档位 / 任务类型**：标准 / 重核。<!-- dh:task-type:v1 task=DHR_45 type=heavy -->

### 3.3 共同收口条件

- 活动卡均为 heavy：按 dev-harness 做五路复核与有效单测；Core 不读取 task_type。
- 每卡独立 worktree；真实跨项目样本、各项目 Authority 和环境操作须在开工时另行确认。
- 需求境证据必须含真实跨项目时间线、逐项目 workspace/HEAD、加入/不加入分支和资源释放；不能以单测代替。
- 组件接线、跨项目权限和 PlanHome 启用标完成前必须有 `verify(dh-relay):`；密钥值零入仓。
