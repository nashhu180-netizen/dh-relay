- 运行现场目录：测试一律用临时目录 `Join-Path ([IO.Path]::GetTempPath()) "relay-test-<套件名>-<随机>"`，用完 `Remove-Item -Recurse -Force`；**禁止读写 `.dh-runtime/`**（dh-crew 现场）。

- 事件 ID 确定性：`EV-<run_id>-<6 位序号>`，序号 = 当前 `events.jsonl` 行数+1（**不存进 relay-state.json**，这样"拒收"路径不改动 relay-state.json 字节）。

## 关键决策（主控定·worker 照做，一句话各一行）

- **K-1 事件 kind 不扩枚举**：v1 event kind 冻结不动。proposal 被拒 → 追加 `plan_proposed` 事件带 `reason='proposal-rejected:<码>'`；proposal 晋级 → 先 `plan_proposed`（无 reason）再 `plan_activated`。Runner 自己判出的停滞/非法观测 → `observation` 事件带 reason。启动失败 → `launch_failed`。
- **K-2 事件 kind 与身份 verdict 的映射**：result 的 `verdict='stale'` **或** reason 为 `stale-plan` 或 `stale-generation` → `result_stale`；其余非 accept → `result_rejected`。checkpoint 任何非 accept → `checkpoint_rejected`（无 stale kind）。
- **K-3 receipt 先于 spawn**：`session_id` 由 Runner 在写 receipt 时指定（`S-<四位序号>`），adapter.launch 必须以**这个精确句柄**建会话并原样返回；不等 → `launch_failed` reason `launch-handle-mismatch`。receipt 落盘（CreateNew）与 `launch_receipt` 事件都在调用 adapter.launch **之前**。
- **K-4 心跳不算进展**：`last_progress_at` 只在 launch、终端状态**改变**、checkpoint/result 被接受时刷新；同状态 probe 只追加 `observation` 事件，不刷新（否则停滞永不触发）。
- **K-5 同状态 checkpoint 不算转换**：checkpoint.status 与当前 result_status 相同（如 working→working）= 进度更新，接受、不查矩阵；不同才用 `Test-RelayResultTransition` 判定。
- **K-6 fail-closed 的统一落点**：任何异常（launch 失败/期限超时/probe 连败/停滞/exited 无结果/非法观测转换/worker 自报 interrupted_unknown/quota 兜底）→ 该节点 `task_state='paused'` + `pause_reason=<码>` + `scheduling='paused'`，不再被调度、不再 probe；active-plan.json / authority.json **一字节不动**。task_state 只有 `active|paused` 两值，**不得出现任何"完成/失败"字段**（A5）。
- **K-7 quota 兜底**：worker 自报 `result_status=quota_exhausted` 的 final → 矩阵判 `reserved-target-form` → 追加 `result_rejected` reason `reserved-target-form`，然后 Runner 把该节点投影为 `interrupted_unknown`（`working→interrupted_unknown` 合法边）+ paused reason `quota-fallback`；final 文件**不**晋级。
- **K-8 replan 兼容规则（P1 最小）**：v(N+1) 必须 `proposed_by='replanner'`、`run_id` 同、`plan_version` = 当前+1；旧计划每个 node_id 都必须保留且 `role/brief_ref/next_action` 不变；旧节点 `depends_on` 只允许**增加**指向新节点的依赖；可给被阻塞节点加 `resume_from={node_id=自己, attempt_id=被阻塞 attempt}`；违反 → `proposal-rejected:replan-incompatible:<node_id>`。首版（无 active）必须 `proposed_by='orchestrator'` 且 `plan_version=1`。
- **K-9 Runner 与 fake adapter 都没有"回答/输入"入口**：adapter 只有六动词；Runner 全程不调 `suspend`/`resume`（P1 只用 `launch/probe/stop/emit_observation`）；测试用调用日志 + 源码静态扫描双重断言。
- **K-10 依赖冻结用契约函数**：`Get-RelayNodeFreezeSet $activePlan $node` 的结果写进各被冻节点 `frozen_by[]`；同一节点后续 working checkpoint 或 final 被接受时移除。ready 判定 = `scheduling='waiting'` ∧ 全部 depends_on 的 `scheduling='succeeded'` ∧ `frozen_by` 为空 ∧ `replan_required=$false` ∧ `task_state='active'`。
