## 布局与形态

- **Pane 布局是用户习惯，不是临时安排**：主控独占左侧；派出的 pane 一律向右开，多开时右侧上下分、**最多两个**。第二次 split 要显式传目标 pane（`herdr pane split <右上ID> --direction down ...`），别用 `--current`（会切主控自己的格）。派完活、收完原样输出并落盘后**关掉 pane，别攒着**。`herdr pane move` 在同 tab 内是 no-op，重排只能关旧 pane 再 split。
- **施工 worker 默认 codex（2026-09-02 用户改口，原为 Opus）**：`herdr agent start <名> --kind codex --pane <右上> -- --model gpt-5.6-terra -c model_reasoning_effort=high`。本机 `codex` 是 PowerShell 函数壳，固定注入 bypass 沙箱，交互形态下 worker 可自己 commit。Opus 形态在 5 小时额度将尽时会「Inferring… 数分钟只出 1k tokens」，状态栏额度栏消失即是信号。
- **复核者默认只读 codex**：同上加 `--sandbox read-only`；派出前后 `git status --porcelain` 比对证零写入。只读沙盒 `mkdtemp` 被拒，复核者一律**静态审**，测试由主控跑。
- **claude kind 拉起**：`herdr pane run <pane> "claude --model opus --permission-mode acceptEdits"` → 自动识别 → `agent rename`（直接 `agent start --kind claude` 撞 PATH shim）。实例自报模型（SessionStart hook）与启动参数可能矛盾（启动 `--model opus`、hook 报 fable）——记「形态待证」并存登记。
- **用户会自己给 worker pane 切 auto mode**（shift+tab）省审批：看到 pane `focused:true` + 状态栏 `auto mode on`，先问一句是不是用户切的；确认后主控从「逐次放行」改为「收工时整体核 diff / 证据」。主控也可代切：`herdr agent send-keys <名> shift+tab` 循环（acceptEdits → plan → auto），每按一次读状态栏确认。

## 提交与催收

- **codex TUI 长中文 prompt 会停在输入框不提交**：`agent prompt` 后 `agent get` 若仍 `idle/done`，读 `--source visible` 看提示符下是否残留文本，残留就 `send-keys <名> enter`。判据 = 输入框清空 + status 转 working。
- **`agent read --lines N` 在 blocked 状态下报 `agent_not_idle`**（alternate screen 只能 idle 时滚）：blocked 时改 `--source visible` 看审批框；收长输出等 idle 后用 `--source recent-unwrapped --lines 400+`，从最后一个 `## 形态自述` / `• PASS|不通过` 切片落盘。
- **审批放行**：`send-keys <名> enter` = 选中项（默认 1. Yes）；`down` + `enter` 选第 2 项。放行前读 worker 的脚本内容（scratchpad 路径在审批框里）；同一脚本多轮时用文件 hash 核「脚本没变」再自动放。
- **后台催收**：`herdr agent wait <名> --timeout <ms>` 挂后台，settle 到 idle/done/blocked 即返回（偶发 exit 66 无输出，重挂即可）。**codex worker 在 auto/bypass 下不会 blocked**，wait 只会在 idle/done 返回。
- **被派出的 codex reviewer 原文可事后找回**：`~/.codex/sessions/` 有全文（含沙盒形态），落盘漏了可去补。
