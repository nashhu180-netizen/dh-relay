## 2. 「只写不删」显式选择核对

- 设计 §12 末段（第 1330 行）原文：「程序**不产生临时文件**（纯追加），无临时文件回收问题。『只写不删』是**显式选择**：账本与决策文件每计划几百行文本，量级不构成容量风险，且是复盘唯一证据。」
- §15 自查行（第 1374 行）复述同一口径：「§12 已逐类写『谁删 / 何时删 / 删失败怎么办』；纯追加后无临时文件问题；『只写不删』为显式选择并给了理由。」
- **核对结论：成立。** 原文逐字含「显式选择」字样并给出两条理由（①每计划几百行文本、量级不构成容量风险；②复盘唯一证据），另附支撑声明（程序纯追加、无临时文件回收问题）。
- 实现侧复核：运行路径属实——`add` 的唯一写是 `open(ledger_path, "a")` 纯追加（`relay_log.py:2487`），无覆写、无删除、无临时文件；`status` / 普通 `lint` 全程只读（§3）。**边界**：`lint --amend-check`（HC-RL-A122）会在调用方给的 `--snapshot-dir` 下建受管快照目录（`_restricted_dir` :933、`_store_raw_copy` :960、`manifest.json` :1402），成功时清理快照目录——`_remove_snapshot_dir`（:1239–1241，内为 `shutil.rmtree(..., ignore_errors=True)`，调用点 :1413/:1440/:1488）与 `snap/"verify"` 上的直接 `shutil.rmtree`（:1399）；恢复校验失败时**故意保留快照交人工接管**（:1434–1439）。即「不产生临时文件」对运行路径（add/status/普通 lint）成立；amend-check 是唯一例外路径，其「失败保留交人」与 §12「报错交人、不强删」同向（详见 findings F-001 候选观察）。

## 3. `status` 无自动删除：代码路径证据

HC-RL-A13 的机器证要求「`status` 不做任何自动删除」。沿调用链核实（`tools/relay-light/relay_log.py`，工作树基线 `f6062c8`）：

**调用链（只读）**

1. `main` 分发：`status` → `_status_command`（:3249–3250）。
2. `_status_command`（:3190–3201）只做四件事：
   - `_runtime_plan(plan_dir, config)`（:1531–1538）→ `lint_plan`（:519）→ `parse_plan`（:407），唯一文件动作是 `plan_path.read_text(encoding="utf-8")`（:411）；
   - `read_ledger(Path(plan_dir)/"relay_log.jsonl")`（:1545–1581），唯一文件动作是 `ledger_path.read_text(...)`（:1551），文件不存在时返回空账本（:1548–1549）；
   - `derive_status(plan, entries, limits=config.limits)`（:2757–2944），docstring 自述「a read-only projection: it neither validates lifecycle order nor judges any produce」（:2766–2767），内部全部为内存投影（其调用的 `_node_closed`/`_stage_of`/`parse_stage_result_note`/`_note_tokens`/`_ledger_warnings`/`_latest_for_instance`/`_idle_seconds`/`_unclosable_reasons`/`derive_last_writer`/`_suggested_action` 均为纯函数，不触文件系统）；
   - 输出：`print(json.dumps(status_document(status), ...))`（:3197–3198，`status_document` :3081 纯构造 dict）或 `sys.stdout.write(render_status_text(status, plan_dir))`（:3199–3200，`render_status_text` :3150 纯拼字符串）。

**全文件副作用清单（证明 status 不可达删除）**

`relay_log.py` 全文（3265 行）所有文件系统写/删操作仅两处归属：

- **账本追加**：`open(ledger_path, "a")`（:2487，在 `append_event` 内，仅 `add` 路径可达）——纯追加，无删除。
- **`lint --amend-check` 快照机制**（HC-RL-A122）：`os.mkdir`（:933 `_restricted_dir`、:1115 `_require_plain_parents`）、`os.rmdir`（:943）、`os.open` 写（:950 `_restricted_writer`、:1145 `_restore_one_path`）、`target.unlink()`（:1132/:1144/:1159/:1166 `_restore_one_path`）、`shutil.rmtree`（:1399 为 `snap/"verify"` 上的直接调用；`_remove_snapshot_dir` :1239–1241 的调用点为 :1413/:1440/:1488）。这一簇只从 `_lint_command` 的 `amend_check` 分支（:1511–1514 → `_validate_amend_before`/`_validate_amend_after`）可达；CLI 层（:3229–3240）要求 `--amend-check` 与 `--repo/--snapshot-dir` 同给才进入。

`status` 分支（:3249–3250 → :3190）对上述任一写/删函数**零可达**。

**实测旁证**

收口时对真计划实际执行过 `status`：RLT_12 `progress.md` E-007 记录 `python tools/relay-light/relay_log.py status --plan docs/modules/relay-light/relay/rlt12-win-01` 退出 0、五阶段全 `closed result=done`；执行后 `relay_plan.md`/`relay_log.jsonl` 原样在案（71 行未变）。

**结论与局限**

- 结论：`status` 不做任何自动删除——命令实现侧证据成立，HC-RL-A13 的「`status` 不做任何自动删除」机器证满足。
- 局限：①证据形态是静态调用链阅读＋一次真实执行旁证，不是运行时追踪；②`status` 会**读**计划与账本，并可因非法输入 fail-closed 退出（exit 3/4），但不写不删；③「无自动删除」只覆盖 `relay_log.py` 程序——监工/编排/人执行的关 pane、关终端空间、删 worktree 均在程序外，不在本断言范围。
