## P2

### P2-1 — L-002 的事实叙述与规则引用两处不准，且未引出预演前身 DR-W-004

- **事实一（叙述不准）**：L-002 写「C1 的 coder#1 与 checker#1 **都先记了 `done`**，checker **才**报 FAIL p1=3」。账本实际是：seq 16 `done coder#1`；seq 20 `done checker#1`，而**该 done 事件的 note 原文就是 `check.C1.md FAIL p1=3 p2=0`**。对 coder 而言「先 done 后 FAIL」成立；对 checker 而言 **done 与 FAIL 是同一条事件**，不存在先后。这处不准恰好削弱了 L-002 自己开的药方（「复核方在判 PASS 前也不记终态」）——真正的纪律失误正是 checker 在报 FAIL 的同时把自己终态化了。
- **事实二（规则引用不全）**：L-002 的标题是「复核触发条件不该挂在终态事件上」，承重的是 **A70**（`on:done:<X>` 要求 X 最新事件必须是 `done`），但条目只引了 `HC-RL-A60` 与 `HC-RL-A49`，**A70 没出现**。F-008 三条都引了（`findings.md:17`）。
- **事实三（预演前身缺失）**：Windows 预演 DR-W-004 已记「`checkpoint` 不能落 terminal agent（A60：对 done 的 builder#1 写 checkpoint 被拒）」并给出挂 live reviewer 的 `routed_to=<worker>#<n>` 绕法（`evidence/win-dry-run/README.md:103`）。L-002 未提它，读者无从分辨本轮**新增**的是哪一层。**我核过：L-002 确实不是 DR-W-004 的改头换面**——新增的是「带 trigger 的复核路上该绕法整体失效」，这一层预演里没有，仓内实证在 `dispatch/monitor-X1.md:206`～`:209`。
- **整改**：把「checker 才报 FAIL」改为「**checker 在同一条 `done` 事件里报出 FAIL**」；规则句补 `HC-RL-A70`；去重段加一句「DR-W-004 已覆盖 A60 单点与 `routed_to` 绕法，本条新增的是 trigger 语义层——该绕法对带 `on:done:` 的复核路无效」。

### P2-7 — 本轮真实发生但未被记下的两条教训

我读完 71 行账本与六份派单后，找到两条有仓内实证、可迁移、却未进任何候选的教训。**作为 P2 提出并附候选措辞**，不代裁决。

**（a）完成信号文件写在 commit 之后，收口时必然变成 untracked 残留**

- 实证：`dispatch/monitor-F1.md:97`～`:109` 的「RLT_21 树的未提交文件（实测 `git status --porcelain`，全部 untracked）」列出六个文件，并注明「`done.scribe.R1.md` 是 R1 scribe 写在 commit 之后的信号，**不是遗漏**」；同段写死「scribe 逐个点名 `git add` 即可，**禁 `git add -A` / `git add .`**」与「开工前自己复核一次这个清单，多出别的文件先停下报编排，不要自己清理别人的工作区」。
- 为什么是教训：`done.<role>.md` 独立信号文件这个约定来自预演 DR-W-010 的建议（`evidence/win-dry-run/README.md:109`），但**它的副作用——信号必然晚于 commit、于是稳定地在收口积一批 untracked——在预演里没出现**，是本轮真跑才暴露，且已逼出一条具体操作纪律。
- 候选措辞：
  > **完成信号文件（`done.<role>.<node>.md`）按约定写在 commit 之后，因此每个节点都会留下一批 untracked 信号文件；收口节点必须拿到一份点名清单逐个 `git add`，禁用 `git add -A` / `git add .`，并在开工前自查一次 `git status --porcelain`——清单外多出的文件一律停下报编排，不得自行清理他人工作区。**

**（b）一张卡可以在自己的三路复核一次都没跑的情况下随「整体授权」合入 master**

- 实证：`workspace/RLT_12/review.md` 的「独立复核区」三行（code-round1 / requirement / lesson）复核者、结论、发现级别、报告**四列全部是「待填」**，「Normal Recipe 路径登记」三行状态全部是「待执行」；而该卡已于 2026-09-15 squash 合入 master（`7981556`）。本文件的存在本身就是这条教训的直接后果。
- 为什么是教训：可迁移，且与 L-008 不同源——L-008 讲的是编排卡**没有记录位**，本条讲的是**复核未执行却通过了合并闸**，成因与整改都不同。
- 候选措辞：
