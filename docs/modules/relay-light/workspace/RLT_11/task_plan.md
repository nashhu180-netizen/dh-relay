- **目标**：以 RLT_12 真计划 `rlt12-win-01` 的产物为样本，逐类核对设计 §12 的「谁删／何时删／删失败怎么办」；形成 relay-light 现役实现侧的退场说明，并单独证实 `status` 不自动删除。来源：DevPlan §RLT_11「目标」「验收口径」；设计 §12、HC-RL-A13；dispatch `W1-builder.md`「C1 退场核对」。
- **要改的文件**：新增 `docs/modules/relay-light/as-built/持久化产物退场核对.md`；本卡 `progress.md` 仅追加本批证据索引与结果。两者都在允许路径内。不改 RLT_12 真计划、设计或程序。
- **具体动作**：只读检查设计 §12、`docs/modules/relay-light/relay/rlt12-win-01/relay_plan.md`／`relay_log.jsonl`、RLT_12 工作区的实际工件与收口记录，并检查 `tools/relay-light/relay_log.py` 的 `_status_command` 调用路径。新说明中逐类列 §12 六类产物，每行写设计的三问答案、真计划或工作区的实际路径／存在性、实现归属与差异；真计划不能证明的删除／失败情形标为「未实测」，不得推定成功。单列「只写不删」选择、设计理由、`status` 无自动删除的代码路径证据及局限。`status` 的判断要沿其调用链确认，不能因源码其他命令含清理操作就误判 status。源引用用小节、文件行号或稳定的产物路径。
- **完成判据（机械核验）**：新说明存在；六类逐类各有「谁删／何时删／失败处理／真计划证据」列；含设计 §12 的显式选择及理由；含 `_status_command` 到 `derive_status`／输出的具体源码锚点和「无自动删除」结论；明确区分已实测、仅设计声明、未实测。核对 `git diff --name-only`、`git diff --cached --name-only`、`git ls-files --others --exclude-standard`，本批新增／改动仅限上述两文件；必要时用 `git diff --check`。不得通过改源码来使结论成立。
- **预期证据落点**：`as-built/持久化产物退场核对.md` 的核对表和 A13 断言索引；`workspace/RLT_11/progress.md` 的 C1 记录。真计划与 RLT_12 产物为只读来源，不在本批重写。

## C2 · §15 三条教训逐条回流

- **目标**：将设计 §15「教训候选（本卡新增）」的三条原意逐条、独立提入共享教训库候选，不扩成新需求。来源：DevPlan §RLT_11「目标」「实施提示」；设计 §15 第 1378 行；dispatch `W1-builder.md`「C2 教训回流」。
- **要改的文件**：`docs/modules/dh-relay/knowledge/教训库-候选.md`；本卡 `progress.md` 仅追加本批证据索引与结果。不得修改现有候选条目或其它文件。
- **三条原句（设计 §15 第 1378 行，逐字基准）**：
  1. ①**阻塞式等待放后台再结束回合 = 监控断线**（ThinkPad 实测）。
  2. ②**同名不同义的枚举必须分层**：Herdr 的 `done` 与账本的 `done` 一个是「停下」一个是「验收合格」。
  3. ③**两个系统各有一个叫 workspace 的东西时必须先改名再设计**，否则每条规则都要带定语。
- **具体动作**：施工时重新只读确认候选库末号与既有格式、重复语义及设计 §15 原文；按文件现有 `### 候选-N · …` 块格式在末尾续三号（W1 观察末号为 87，预期 88–90，若施工前变化则以届时末号为准且绝不复用）。每块候选的「教训表述」逐字保留上方对应完整原句；背景、现场现象或扩写说明只能放在独立字段，不得改动原句措辞。分别填写触发场景、建议分类、来源、疑似重复、现象、反思、建议后续动作及「状态：待裁决」；每条来源同时回链设计 §15 及经核实的现场卡号／证据。现场卡号无法由现有材料核实时停在本批 BLOCKED，登记缺口，不能猜。仅追加这三条，不整理既有库。
- **完成判据（机械核验）**：文件末尾恰新增三个连续且不复用的候选号（施工前重查末号，W1 观察为 87）；三块各含上方对应的完整原句，并与设计 §15 第 1378 行逐字比对通过，任何字词、限定条件或标点缺失／改写均不通过；每块同时有设计 §15 与经核实的现场卡号／证据两类来源回链，状态为「待裁决」；既有条目零改动。以 `git diff --` 目标文件、`rg '^### 候选-'` 与 `git diff --check` 核验；四集合检查确认本批仅目标文件与本卡 `progress.md` 改动。
- **预期证据落点**：教训库新增的三个候选块；`workspace/RLT_11/progress.md` 的 C2 记录与三号索引。C2 不依赖 C1 的说明，可独立开工、独立验收。
