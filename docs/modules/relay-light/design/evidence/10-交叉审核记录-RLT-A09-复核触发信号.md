## 一、触发事实

真计划 `rlt12-win-01` 在 **C1 节点**撞上「复核打回后节点内无合法返工路径」，登记为 `workspace/RLT_12/findings.md` 的 **F-008（P1）**。三条现行规则互锁：

| # | 规则 | 出处 | 效果 |
|---|---|---|---|
| ① | `on:done:<X>` 的 trigger 前置要求 X 在本节点最新事件为 `done`，否则退 2 报 A70 | `relay_log.py:1649`-`:1665`；design §3.5、§11 A70 | 「记了 done 才准拉复核」 |
| ② | `done` 属终态，终态实例不得再挂任何事件，退 2 报 A60 | `relay_log.py:1818`-`:1819`；design §3.4、§11 A60 | 「记了 done 就不能返工」 |
| ③ | 重拉只在前一实例 `agent_lost` / `cancelled` 或本阶段已 `failed` 时放行，否则退 2 报 A49 | `relay_log.py:1806`-`:1811`；design §11 A49 | 「也不能换个实例重来」 |

账本实证（可逐条回查）：**seq 20** `done checker#1` 落下的结论是 **FAIL p1=3 p2=0**；**seq 21** 的 `node_close` note 原文写明「三 agent 均 done；check.C1.md FAIL p1=3；**节点内无合法返工路径（A49/A60）**，三条 P1 由编排裁决带入 C2 返工」。C2 起编排冻结「PASS 前谁都不记 done」的纪律绕开（seq 25 / 26 / 27 三条 live checker 的 `checkpoint` 路由，seq 33 PASS），但该绕法**只对 trigger 留空的角色有效**——X 阶段 reviewer 走 `on:done:coder` 的硬闸绕不开。本轮 X1 两路恰好都 PASS（seq 59 / 60），返工边未被真正踩到；**「若任一路 FAIL 会原样复现 C1 事故」是推论，不是实测**，两轮 fresh 复核均独立确认该标注。

用户 2026-09-15 对 F-008 只裁决了三句方向：复核类 agent 的 trigger 不再要求被依赖方处于终态、改为承认非终态「待复核」信号；复核方同样留活口，不判 PASS 不记 `done`；轮次上限沿用 `limits.rework_max_rounds=2`，超限仍走 strategist → 用户闸。**信号名、事件名、码位、适用阶段、验收编号、lint 是否拒旧写法、计数归属，均不在这三句之内**，由候选稿提案、由本记录第三节的六项裁决闭合。

### 定向复审（attempt 2）

- 范围：仅复核 attempt 1 的 P1-1～P1-3 与 P2-1～P2-5，未重开全面复核。对象为候选稿 v2（434 行）。
- 结论：**REVISE；剩余 P1=2（P1-1 / P1-2），P2=1（P2-1）**。
- P1-1 的余留判据：v2 要把 R 的 reviewer 改成 `on:review_ready:coder` 并在示例中写 `agent_launch coder#1`，但 R 模板只有 reviewer 与 scribe、没有同节点 coder；`A59` 要求非豁免 agent 名字在本节点 agent 表（`relay_log.py:1584`-`:1585`），`A71` 要求 trigger 只引用同节点 agent（`:591`-`:603`），故 v2 的 R 写法会被这两道现成闸直接拒，落不了地。
- P1-2 的余留判据：A144 只要求「存在一条」匹配 `checkpoint`，未要求它属于送审方**当前实例**且仍是该实例**最新事件**；`_latest_by_name` 只按名字跨 attempt 取最新行（`:1588`-`:1603`），于是旧 attempt 重放、被普通 `checkpoint` 覆盖、`blocked` 之后三种序列都会被误放行。

### v3 的闭合动作

1. **适用范围收窄**（闭 P1-1）：只适用于送审方与判定方同处一个节点 agent 表的形态；**R 阶段不适用、R 模板不动**，示例从 R 改写为 X。给出三条可核证据——R 节点无同节点送审方（`SKILL.md:74`-`:88` 与实跑 `relay_plan.md` 第 65～67 行，R1 三行 trigger 全空、无 coder）；给 R 写新 trigger 会被 A71 / A59 机械拒绝；R 打回本有合法出口（seq 50 的 `stage_result` 列 5 条 P1 → seq 52 编排开 X1）。
2. **A146 加生效条件**：只在「本节点存在指向该判定方的 ready 信号」时设闸，没有信号就不设闸——R 与一切旧计划因此天然不受影响，向后兼容有结构性保证而不只是「lint 不拒」。
3. **ready 信号绑定实例与最新事件**（闭 P1-2）：A144 要求信号属于送审方当前实例且为该实例最新 agent 事件；A146 要求 `ready_seq=` 指向的事件 `agent` 字段与 `reviewed=<S>#<a>` 逐字同一实例。补三条拒绝反例与一条封口拼接反例。
4. **P2-1 重新分类**：`test_attempt_and_x_loss_stops_trigger_independently` 由「断言将失败」改为「仅补第三计数断言」——给 `LossStop` 增加字段不会让现有属性断言失败。

**v3 无新增未采纳项。** v2 唯一未采纳的那条（把 ready 集合暴露进 `status --json`）已被 attempt 2 判为 CLOSED，理由成立。

| 3 | R 阶段收窄是否接受：R 判定方 `done` 时机仍只由纪律约束、程序不管 | **接受** | R 模板一字不改；A146 对 R 不生效由「无信号即不设闸」保证 |
| 4 | C 的强制性残留是否接受：checker 因 A95 保持空 trigger，程序无法强制「必须先送审」 | **接受，不改 A95** | A95 一字不改；C 的封口顺序只在信号存在时受 A146 约束 |

| 6 | 向后兼容只靠模板与纪律，lint 不强制迁移 | **接受** | A148 钉扩集与混用；lint 不拒旧写法、不报「建议迁移」 |

**裁决之外的事项一律未获授权**：本次裁决**不含** D-start、不含施工、不含 verify 或代签、不含 DevPlan 侧的 `RLT-B-08` 卡号/批次/依赖。
