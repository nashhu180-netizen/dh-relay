# ⚠️ 共创草案 · 未生效 ⚠️ — RLT-A-15：角色名统一（monitor → stage-lead / watcher，账本字段冻结）

- **目标文档**：[`design/01-RelayLight-产品设计与验收.md`](../../01-RelayLight-产品设计与验收.md)（行号取自 master `724506c`）
- **事件 ID**：`RLT-A-15`（design/01 当前活动声明到 `RLT-A-14`）；stage = **A-full**（改变验收条目 A131/A163/A164/A165/A167 措辞与 single-task phase 闭集 → 命中「改变验收」升级判据）
- **GitHub**：Issue **#70**；分支 `plan/RLT_A_15`
- **状态**：v1 · 未生效

## 1. 为什么改

2026-09-23 #62 把 SKILL / adapter / AGENTS 里的「监工 monitor」更名为 **stage-lead**，并把 single-task 的只读观察者定名 **watcher**，但明确留下两处未改：①`design/01` 正文仍写「监工」（117 处）、「monitor」角色；②single-task 的 `phase=monitor` 与 `roles.toml` 的 `[monitor]` 段沿用旧名。结果是用户打开新终端启用 relay-light 时，single-task 仍拉起名为 monitor 的常驻 agent、`roles.toml` 仍有 `[monitor]` 段而无 `[watcher]`（RLT_18 F-011）。用户 2026-09-28 要求「把名字统一」，并点选只统一角色层、账本字段冻结。

## 2. 划界

| 层 | 处理 |
|---|---|
| **角色层**（人读的角色名、职责描述、角色表、配置段名、single-task phase 名、验收条目正文） | 统一为 **stage-lead**（阶段主管）/ **watcher** |
| **冻结机器字段**（账本与 `status --json`） | **不改**，在 §0.2 与 §3.3 加注：它们是 stage-lead 的历史字段名 |
| **历史记述**（顶部 `RLT-A-xx` 活动声明块、§15 形成史、引用的用户原话） | **不改**（记录当时的措辞） |

冻结词清单（出现即保持原样）：`monitor#<n>`、`by=monitor` / `"by":"monitor"`、`monitor_launch`、`monitor_restart`、`monitor_relaunch_count`、`relaunch_monitor`、样例账本行中的上述字段。

## 3. 改名规则（design/01 正文，§0 至 §14）

| 规则 | 内容 |
|---|---|
| R1 | 角色中文名「监工」→「stage-lead」；§0.2 核心术语与 §2 角色表首次出现写「**stage-lead**（阶段主管）」。含「当班监工」「新监工」「重拉监工」「监工挂掉」等所有复合用法 |
| R2 | 角色表 `**监工** monitor` 行 → `**stage-lead**（阶段主管）`；「谁拉起」列的「监工」→「stage-lead」 |
| R3 | 正文把 `monitor` 当**角色名**用的地方（不在冻结词清单内的）→ `stage-lead`（完整模式）或 `watcher`（single-task，见 §4） |
| R4 | 冻结词清单内的字段保持原样；首次在 §3.2/§3.3 出现处加注「`monitor` 为 stage-lead 的冻结账本标识，历史命名，不随角色改名」 |
| R5 | 历史记述不改（见 §2） |

晋级机检（promotion-check）：晋级后 design/01 §0–§14 中 `监工` 计数 = 0；`monitor` 出现处全部属于冻结词清单或历史记述，逐行列表核对。
