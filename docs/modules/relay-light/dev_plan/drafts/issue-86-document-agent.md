## 目标与非目标

在 single-task 内增加一个统一文档 agent，默认使用较低成本模型，从建卡、施工计划、进度、问题记录、复核报告、使用/实现说明到收口交棒，负责本卡获授权范围内的全部人工维护文档。其它角色专注执行、判断与原始事实，不再各自撰写一套文档。

文档覆盖清单：设计及验收、DevPlan、workspace 全套、review/check/decision 正式报告、execution_strategy、使用说明/as-built、教训记录、卡级总表。design/DevPlan 等共享文档的初建或修改由主会话/对应唯一维护方确认权限后委托；workspace 由本卡创建授权覆盖；未获授权的共享文档报告待委托，不冒充已全量同步。

“所有文档”按用途覆盖，不仅限于 Markdown；现有文件格式不因本任务转换。实际写入仍受每次派单精确路径限制。跨仓总表只在登记维护归属与允许路径后委托，不允许扫描并改写整个仓库。

不恢复完整自动化流水；不改变完整 relay 的既有 scribe；不批量关闭旧卡；不更换全部执行模型；不新增 daemon、数据库、事件账本或复杂调度器。当前运行中的卡不强制迁移，历史复核报告和验收事实不重写。

- AGENTS 与两个 adapter 同样规定原写者，实施时必须同步对齐，不留互相矛盾的规则。

## 职责与运行方式

| 角色 | 保留的职责 | 文档 agent 承接 |
|---|---|---|
| 主会话/用户 | 目标、范围、验收、授权与需要人的决定 | 将明确结论写入设计、任务卡、计划和交接资料 |
| builder/执行者 | 施工方案、操作、测试、实际结果及问题判断 | 创建/维护 workspace 文档、施工计划、进度、findings、使用/实现说明 |
| reviewer/decider | 独立检查、问题级别、复核结论或决定 | 根据来源整理报告；不得新增、删减或升级原结论 |
| orchestrator | 已授权派发、运行状态和路由、模型分配决定、协调责任 | 落笔 execution_strategy 与获授权的总表更新，不代替编排决定 |
| 文档 agent | 读取指定证据、起草/更新文档、报告差异与缺口 | 统一文档写入；不运行施工/测试，不决定验收、不派发其它角色 |

原始日志、测试输出、工具生成文件与 durable signals 是事实/控制产物，由原生产者生成，不作为人工文档移交。角色可在自己的原始结果产物内给出简短结论，不要求先写完正式文档再交接。不得把长报告换个文件名继续推给执行者。

文档 agent 直接读取授权路径内的 diff、目标文档、原始结果与必要上下文。输入最少包含本卡/阶段、适用版本或提交、来源路径、明确结论及可写文件；输出为修改文件、关键变更、未解决的信息缺口及自己的完成信号。复用现有派单和工件，具体 signal 字段在实现设计中对齐现有闭集，不预设一个无法运行的新 phase。

按同一张卡复用文档会话、按需唤醒；模型配置集中在现有角色分配入口，默认成本档可调整，实际模型与能力在开工时确认，不写死供应商或价格。缺工具/模型能力、反复事实错误时返回有证据的阻塞；换模型沿用现有确认规则，不静默切换。

## 时序、来源与失败处理

1. 建卡先取得用户/主会话确定的目标、范围和验收输入。正式 workspace 尚未存在时，由主会话使用本 Issue/规划工件定位并授权文档 agent 创建，不依赖“先有 workspace 才能创建 workspace”的循环。无需为本次文档规划启动这个尚不存在的角色。
2. 施工计划由有职责的角色提供方案并确认关键内容。影响后续执行的计划未确认前不能消费；日常记录可在安全边界批量更新，不要求每个工具调用后启动文档 agent。
3. 每次写入前核对输入版本、源文件和目标现状；同一文档只有一个当前写入者。与被测现场有关的文档在验证期间冻结，避免改变候选版本。多卡共享总表由登记维护方顺序委托，不能各派一个文档 agent 并写。
4. reviewer 独立形成最小结构化复核结果（问题定位、级别、verdict、证据与候选版本），不要求其先写完整 Markdown 报告；这个结果属于控制/证据产物，不以扩展名规避统一文档职责。文档 agent 起草/写入正式报告后由原 reviewer 对关键结论和对应版本确认；独立性、原始来源和确认记录可追溯。正式报告确认后，reviewer 才发可被路由消费的 PASS/DONE。文档 agent 的 DONE 只表示本次文档处理完成。如确认发现代笔错误，保持本轮未 PASS，由文档 agent 更正；若原判断本身改变则保留修订来源，不借文字确认绕过实质复核规则。字段级来源确认不构成新一轮复核，不新增 attempt、不重置整改额度；后续按既有 Recipe 开展的 fresh 复核必须独立检查候选与原始证据，不能用文档摘要替代。
5. 路由前由 orchestrator 机械核对责任方确认引用、角色、候选版本与最终报告版本一致，语义正确性由原 reviewer/责任方确认，编排不代审业务。修改报告后原确认失效。该要求首先是可演练/审计的协议约束，现役 prompt 与 Herdr 不提供沙箱或程序强制门；若正式设计要求自动拦截，须列明实际消费入口、校验实现和反例测试，不能凭文本宣称硬阻断。决策或运行配置同样由责任方确认后才能用于路由；不能只因为文档 agent 写了“通过/已完成”而推进。新实现须明确哪些事实可直接回填、哪些需要责任方确认，不要求逐句文字审阅。
6. 证据缺失、矛盾、版本漂移、写入冲突或会话中断时保留原始事实和待同步状态，报告具体缺口，不猜、不覆盖他人修改、不重跑已完成施工。恢复时比较实际文件和原始结果，避免重复追加；确认过的版本改动后须重新核对。
7. 必要文档未同步不能宣称已交棒或清理任务现场。与这些文档无关且已获授权的卡内工作可继续。实际 commit/push/merge 等仍由原授权执行角色完成，文档 agent 根据结果回填，不以代笔扩大执行权限。

## 开发范围与交付

单卡形成一个可试用的完整交付，不拆成只支持收尾回填的 MVP。

- 协议：`AGENTS.md`、仓内 skill 核心与 Claude/Codex 双 adapter，统一角色职责、派单、单写者、来源确认、失败/恢复、首次建卡和交棒边界。
- 配置与验证：现有模型分配/角色配置、受影响的模板及结构/安装测试；如果需要更改 signal 消费逻辑，在正式设计中明确实际位置和最小改动。
- 文档：相关 single-task 设计、正式 DevPlan、as-built 按现有流程对齐；本次仅提交草案，不直接改变它们。
- 实跑：一张另获授权的真实单卡覆盖建卡至收口全部文档；保留脱敏证据、纠错记录、耗时和可得用量。安装到真实用户目录/远端机器以及部署仍不在本次规划授权内。

最小交付物：一套可由单卡编排与执行者直接使用的统一文档协议、两端可用的角色配置/派单约定、必要验证和一张真实单卡试跑报告。正式施工精确路径与步骤在 D-start 工作区冻结。

## 验收候选

以下为本需求候选口径，正式设计定稿时分配模块验收 ID；不是已通过记录。

| ID | 类型 | 可观察结果 |
|---|---|---|
| DA-01 | 机器证 | 一张卡从 workspace 创建至最终交棒，各类人工文档均由文档 agent 写；其他角色仅生成原始事实/控制产物，无只做收尾回填的缺口 |
| DA-02 | 机器证 | 原始测试/复核/决定来源与版本可追溯；故意将 FAIL 改写成 PASS 或遗漏 open finding 时，责任方核对拒绝，编排按协议停止消费；保留拒绝及未推进的实跑记录，不冒充程序硬门 |
| DA-03 | 机器证 | 精确允许路径与单写者可核对；越界、同时写总表、未确认计划/报告的场景通过演练发现并拒绝继续消费；明确核对角色、来源及版本。协议检测/审计不等于沙箱硬隔离 |
| DA-04 | 机器证 | 缺证、冲突、过期输入、中断后恢复均保留事实且不重复写入、不错误推进；文档完成信号不替代 reviewer/执行者信号 |
| DA-05 | 机器证 | 模型分配、能力预检和两份 adapter 对齐；默认成本档可配置，角色未获批准或能力不足不静默启动/替换 |
| DA-06 | 机器证 | 相关测试、完整 relay 回归与 PR 必需 CI 满足；以反例演练验证错误结论被责任方拒绝、编排不继续路由，区分自动测试和协议演练 |
| DA-07 | 机器证 | 真实单卡报告记录文档侧用量/费用可得值、交接/核对耗时、事实纠错与重试次数；费用不可得标未知，不编造降本比例 |
| DA-08 | 人判 | 用户查看真实单卡样例后判断“文档已整体交出去、执行侧负担减少且可接受”；未得到判断不代签 |

试跑报告使用现有工件的一张表，字段为角色/模型、调用次数、可得 token/费用、交接及核对耗时、纠错/重试次数、可比基线及限制。没有费用时保留可得用量与耗时；由主会话展示、用户判断是否值得继续，DA-08 未判定时只报告已取得的机器试跑证据。

成本收益是试跑评估结论，不预设通过阈值或承诺节省百分比。若无可比基线，只报告本次实测，不声称已证明降本。
